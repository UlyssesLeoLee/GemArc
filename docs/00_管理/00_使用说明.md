## 使用前提与标准定位

- **对象**：GemArc 从现有 Skill/Viewer 演进为独立 Core + Component Registry + MCP 接口的目标产品。
- **事实基线**：GitHub `UlyssesLeoLee/GemArc`，`main` 树 `777af2a7e3aeadc5e05742074097c851c8b72301`；以 2026-10-25 查询结果为准，尚未开展源码本地构建/运行验证。
- **区分**：`AS-IS` 仅指仓库文件和说明可以证实的能力；`TO-BE` 为拟开发需求，状态一律不是“实现完成”。
- **依据**：IPA《共通フレーム2013》流程及裁剪思想；IPA《非機能要求グレード2018》六大分类；ISO/IEC/IEEE 42010:2022 的架构描述思想；2026-07-28 MCP 规范。
- **重要限定**：IPA 并未规定必须提交本资料包中的全部文档，也没有官方统一的“IPA 合格文档包”格式。本套资料为按这些资料裁剪的项目工程交付结构；**不代表 IPA 官方审查、认证或 42010 符合性评估**。

## 阅读顺序

1. `00_管理/01_文档清单与状态.md` → `01_要件定义`（为什么与做什么）。
2. `02_基本设计`（系统边界、模块分工、外部接口、UX、非功能设计）。
3. `03_详细设计`（Schema/工具契约/编译算法/模拟规则）。
4. `04_测试设计`（UT→IT→ST→UAT；仅测试设计，尚未执行）。
5. `05_项目管理`（风险、迁移、运维、变更、审查）。
6. `06_图表` 中的 `.mmd` 为 Mermaid 源文件，各 MD 直接引用相对路径；`07_台账` 中的 XLSX 便于评审与跟踪。

## 审核状态规则

`设计基线（待评审）` ≠ `已审批`；`未实施` ≠ `已实现`；`未执行` ≠ `测试通过`。签核人/实际执行者/测试日期必须在项目实施时补充真实信息。
