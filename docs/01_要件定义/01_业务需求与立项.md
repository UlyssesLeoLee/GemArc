# 业务需求与立项定义

> 文档编号：BUS-001 ｜版本：1.0 ｜日期：2026-10-25 ｜状态：设计基线（待评审）  
> 产品：GemArc MCP — 5D Design Scaffolding & Architecture Compiler  
> 说明：本文件为目标设计，不代表目标功能已实现或已测试。

## 1. 背景与业务问题

跨项目生成架构 5D HTML 时，AI 反复产生 Three.js 场景、标签系统、图论显示、时间轴及样式，导致 Token 浪费、交互分化、测试困难和事实可信度不足。目标是“统一工程基座，AI 专注业务语义”。

## 2. 项目目标（BO）

- BO-01：同等功能的标准公共代码以组件库复用，不再为每个项目重写。
- BO-02：跨项目交付同一视觉语言和交互标准，避免以提示词稳定性替代工程约束。
- BO-03：任何视图都能追溯到项目模型及证据；假设与实际结果明确分离。
- BO-04：完整 5D 网站与模型、测试报告可以独立交付，脱离 Agent 查看。
- BO-05：通过 MCP 统一接入不同 AI Client，同时可由 CLI/CI 使用核心能力。

## 3. 利益相关者（ステークホルダー）

| 角色 | 关注点 | 成功判定 |
|---|---|---|
| 架构设计者 | 架构事实准确、可审查、信息增益 | 100% confirmed 事实可追溯 |
| AI Agent 开发者 | 工具易发现、减少重复代码 | Token 对照达标 |
| UI/UX 使用者 | 各维界面一致、认知负荷低 | 交互场景验收 |
| 安全审查人员 | 不可信代码/文件隔离 | 风险测试无高危遗漏 |
| 维护人员 | 升级兼容、故障可诊断 | Build Lock 与日志完整 |
| 业务审批者 | 投入产出与阶段交付 | UAT 通过并签核 |

## 4. 范围

**包含**：MCP Server、核心模型、模板库、组件库、1D–5D HTML、原型、4D/5D 模拟、质量验证、导出与迁移。

**不包含**：为所有仓库自动证明真实生产因果；在没有证据时推断运行 SLO；直接成为线上应用生产部署平台；读取未授权私有文件；假定每个 View 必须生成全部五维。

## 5. 分期

- Phase 1：P0 中优先落实模型、MCP、模板/组件资产、基础 2D/3D、打包/验证闭环。
- Phase 2：完整 4D/5D、原型编排和大规模性能改善。
- Phase 3：P1/P2 扩展生态、增量与多 Agent 治理。

P0 定义为正式功能基线；分期将进一步以 WBS 固化，不能把 MVP 阶段完成误认为全部 P0 已实现。
