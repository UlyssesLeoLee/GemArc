# 系统方式与总体架构设计

## 设计方针

MCP 只是对外接口：`MCP Adapter → Application Services → Core Engine → Registry/Repository → Build Artifacts`。核心业务模型独立于 LLM、Web Viewer 和传输协议，CLI/CI 均应复用同一服务层。

## 模块构成（システム方式設計）

| 模块 | 职责 | 输入 | 输出 | 故障隔离 |
|---|---|---|---|---|
| MCP Adapter | 工具发现、入参验证、协议映射、权限 | JSON-RPC | 结构化结果/错误 | 工具超时和取消 |
| Inspector | 文件发现/事实候选/来源链 | 受信任范围内文件 | Evidence Index | 不可信内容只作数据 |
| Model Core | Schema/稳定 ID/事实状态/视图查询 | Evidence | Architecture Model | 模型校验失败阻断 |
| Registry | 组件/模板版本选择、依赖与许可 | Component Query | Locked Components | 隔离恶意组件 |
| Compiler | 模型→视图→资源→站点 | Model+Lock+Preset | HTML/Assets/Report | 临时目录原子发布 |
| Dynamics Engine | Case 的状态和时间演化 | Event+FSM | Timeline/State snapshots | 超时/最大事件数 |
| Causality Engine | 规则组合、干预与结果解释 | Causal Rules | Outcomes/Provenance | 无证据不作事实判断 |
| Validator | Schema、语义、质量闸门 | 中间产物/站点 | Report | 避免验证器修改事实 |
| Exporter | 单站点、模块 ZIP、文档打包 | 成品与锁文件 | ZIP/manifest | 不包含绝对主机路径 |

## 执行与存储选择

- 单机 local-first：文件系统保存模型/报告/构建结果；Dexie 在浏览器端只缓存可丢弃的 View 状态，不能作为唯一事实来源。
- 浏览器 Runtime：Graphology、Dagre、Konva、Three.js、Dexie 按能力加载；安全/CSP/许可证由构建器检查。
- 可扩展 HTTP 服务为后续选项；本期无强制数据库服务器或 SaaS 服务依赖。
- 所有外部输入均按不可信数据处理；工具权限由明确白名单与准入审计限制。

## 技术决策

核心语言建议 TypeScript（MCP 与 Renderer 同类型模型、便于统一 Schema），迁移期可保留现有 Python 脚本适配器；具体语言选择在 ADR 中冻结，不将候选技术写成现有实现。
