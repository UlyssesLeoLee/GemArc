## 概念对象

`Project` → `Source` → `Evidence` → `Architecture` → `Node/Edge/Interface/Constraint` → `Viewpoint/View` → `Scenario/State/Event` → `CausalRule/Intervention/Outcome`。

[ER/逻辑数据关联图](../06_图表/02_model_er.mmd)

## 核心关系

- Node : Edge = 1:N (端点由 `sourceId/targetId` 指向稳定 Node ID)。
- Evidence : Node/Edge/Rule = N:M（部分对象未知，不得伪造证据）。
- View : Node/Edge = N:M（View 是投影，不保有第二份实体事实）。
- Case : Event = 1:N，Event 有时间、主体、输入、状态转换结果。
- Intervention : CausalRule = N:M，输出应指明假设基础及版本。

## 证据状态

`confirmed`=存在可靠来源；`assumed`=经过声明的假设；`illustrative`=纯演示；`unknown`=缺失或矛盾。`confirmed` 不自动意味着“经过运行验证”，单独标 `observed/modelDerived/hypothetical`。

## 视点要件（ISO 42010 风格）

每个 Viewpoint 记录：stakeholders、concerns、questions、modelKinds、notation、qualityChecks。常见 12 个候选 View 见现有 `references/viewpoint-catalog.md`；数量并非 IPA 强制。View 应记录 `viewpointId`, `selectedNodeIds`, `edgeKinds`, `dimensionMappings`, `evidenceRefs`。

## 维度关系

- 0D 无独立页面；1D 事实文字；2D 结构与原型；3D 有证据空间分类；4D 时间状态；5D 组合因果。
- 维度切换保持 `selection.entityId`，但镜头、布局、过滤、时刻和干预条件独立存储。
- 视点与维度为正交维度：相同 Logical View 可以有 2D、3D、4D/5D 投影；证据不足时明确禁用高维。
