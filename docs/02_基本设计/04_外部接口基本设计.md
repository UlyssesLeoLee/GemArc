# 外部接口基本设计

> 文档编号：BD-004 ｜版本：1.1 ｜日期：2026-10-30 ｜状态：与当前实现一致（待评审）  
> 产品：GemArc MCP — 5D Design Scaffolding & Architecture Compiler  
> 说明：本文件描述当前已实现的外部接口面；未在真实客户端验证的行为见 `integration-examples/` 中的标注。

## MCP 工具（公开边界）

共 16 个工具，分两个工具集（详细契约见 `docs/03_详细设计/02_MCP工具详细契约.md`）：

- `stateless`（远程默认，8 个，全部只读）：模型随调用内联传入，服务端不保存任何东西。
- `full`（本地默认，16 个）：再加上读写工作区的项目工具；写工具需要用户设置 `GEMARC_ALLOW_WRITE=1`。

| Tool | 集 | 读取/写入 | 输入类别 | 返回 |
|---|---|---|---|---|
| `gemarc_brief` | S | R | project?/section? | 工作指令：槽位、规则、词表 |
| `gemarc_contracts` | S | R | query? | 固定契约、词表、槽位清单 |
| `gemarc_assets` | S | R | query? | 组件注册表条目 |
| `gemarc_new_model` | S | R | system | 空模型 + 槽位清单 |
| `gemarc_validate` | S | R | project 或 model、strict? | errors/warnings + modelSha256 |
| `gemarc_simulate` | S | R | scenario_id、project 或 model、disabled_nodes?、compare_baseline? | trace + 对比 |
| `gemarc_diff` | S | R | base/target 各取 project 或 model | 节点与边的增删改 |
| `gemarc_render` | S | R | model、profile? | `data/*.json` + 固定件描述 |
| `gemarc_inspect` | F | R | path（工作区内） | 文件统计 + 未确认的候选事实 |
| `gemarc_plan` | F | R | project、goals? | 可支持的维度 + 证据缺口 |
| `gemarc_scaffold` | F | W | project、profile? | 固定件 + 空模型 |
| `gemarc_init` | F | W | project | 带示例模型的新项目 |
| `gemarc_model` | F | W | project、replacement_model、expected_sha256 | 新旧 sha256 + 校验结果 |
| `gemarc_build` | F | W | project、legacy_dist?、profile? | 生成的站点 |
| `gemarc_verify` | F | R | project | 文件完整性与 schema 检查 |
| `gemarc_export` | F | W | project | ZIP 路径 + sha256 |

S = 两个工具集都有，F = 只在 `full`。`project` 与 `model` 二选一（`GEMARC_INPUT_003`）。工具名只含 `[a-z0-9_]`，保留 `gemarc_` 前缀（ADR-008）。每个工具都声明 `readOnlyHint`/`openWorldHint`，写工具另声明 `destructiveHint`/`idempotentHint`，客户端据此决定是否要用户确认。

## Resources / Prompts

- Resource（2 个，只读）：`gemarc://registry`、`gemarc://schema/model`。不提供任意文件访问。
- Prompt（1 个）：`gemarc-design`（参数 `project`）。Prompt 不执行文件写入，操作仍经 Tool 授权。
- 并非所有客户端都使用它们（Codex 忽略 prompt，Claude API 的 MCP connector 只支持 tools），所以核心流程只依赖工具，由 `gemarc_brief` 提供完整工作指令。

## 协议约束

传输为 stdio 与 Streamable HTTP（`/mcp`），适配层是官方 MCP Python SDK 2.3.0 的 `MCPServer`。业务工具无会话状态。远程端点只接受 POST，GET 返回 405（ADR-010）。目标规范 MCP 2026-07-28 的 `_meta`、`server/discover` 能力发现由 SDK 适配层负责；适配旧 Client 的兼容逻辑必须独立模块。不使用未协商字段。各客户端（Claude Code、Codex、Hermes Agent）的兼容性结论与验证状态见 `integration-examples/README.md`，其中未真机验证的项均已标注。

## 错误约定

`GEMARC_{DOMAIN}_{NNN}`，例如 `GEMARC_MODEL_012` 关系端点不存在、`GEMARC_AUTH_001` 路径越出工作区、`GEMARC_INPUT_003` project/model 必须二选一。工具返回一段 JSON 文本：`status` 为 `invalid` 或 `error` 时 MCP 结果的 `isError=true`，正文不变；不返回 `structuredContent`（ADR-011）。拒绝类失败带 `diagnostics[]` 与 `artifactRefs[]`，模型校验失败带 `errors[]`、`warnings[]` 与 `summary`。MCP 传输错误与业务验证失败分开表达。
