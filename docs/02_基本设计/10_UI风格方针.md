## 1. 立意：宝石是被切割过的结构

GemArc 的名字里有一个 Gem。宝石之所以是宝石，不是因为它有颜色，而是因为它**被切割过**：它同时具备秩序（对称的面）与光（棱线上的高光）。所以本方针不是「把界面做成宝石的样子」，而是：

- **界面像切面**：信息被切成边界清楚的面，面与面之间是棱线，不是阴影堆叠。
- **三维像宝石**：实体是被切割过的石头，每一面只反射它自己朝向的那一小片天光；关系是穿过它们的光线。
- **光要克制**：宝石的美来自刻面上一小片反射。大面积的亮会把石头变成塑料。
- **同一张纸**：公开站点与后台都是一张纸（第 3 节）。

> v3.4 变更：画风由「暗场里的发光宝石」改为**和紙墨描**（第 16 节）。**几何与语义不变** —— 仍是被切割过的结构，仍由颜色编码事实；变的是**用笔**：不再发光，边是墨线而不是亮棱，底是纸而不是暗场。
>
> v3.5 变更：**宝石恢复半透明**（第 4.2、4.6、13.1、13.3、16.2、16.4 条随之改写）。v3.4 把「和紙墨描」一并理解成「石头也不透」，那是把**画法**（墨描）与**材质**（宝石）混成了一件事 —— 墨描的平面层（第 14 章）确实不透光，但三维宝石是一块被切割出来的石头，透才是宝石的本来面目。现在的口径是「石透、墨不透」：主体不透明度 0.45–0.62、不写深度、双面，因此看得见背后也看得见内刻面；禁的是磨砂与发光，不是透明。退避（focus）随之改回「缩不透明度」而不是「混向纸色」——颜色仍然只编码事实。
>
> v3.6 变更：**宝石恢复光泽**（新增第 4.7 条「切面高光」，第 4.2、4.6、8、10、11、13.3、16.2、16.4 条随之改写）。v3.5 让石头透了起来，却把「透」做成了「平」——半透明而没有反光，读起来是一片染了色的纸，不是一块被切割出来的石头。宝石之所以是宝石，除了**被切割**，还有**光在它表面上的一次反射**。因此在主体之上加一层**切面高光**：只算镜面反射、颜色是纸白、边界是棱线的硬边 —— 不发光、不过曝、不做柔边光晕。
>
> v3.7 变更：**宝石恢复成真正的宝石**（第 4.2、4.3、4.5、4.6、4.7、4.8、8、10、11、12.4、13、16.2、16.4 条随之改写）。v3.6 的「切面高光」是**假反光**：一层加色的平面着色器，画在石头之上，颜色是纸白，边界是棱线 —— 它让石头看起来有光泽，但石头本身仍是纸片。真实的宝石不需要这层东西：它自己会**折射**（背后是什么，石头里就是什么）、会**色散**（白光在切面里散成彩边）、会在刻面上**反光**（每一面只反射它自己朝向的那一小片天光）。因此这一版把三维的石头整个换成**物理材质**（`transmission` + `ior` + `dispersion` + 程序化摄影棚环境），删掉那层假高光与三阶渐变贴图；**墨线**也随之收窄：只留**极细的外轮廓**，内部的棱线交给折射去表现（第 4.8 条）。
>
> 同时新增**切工编码语义**（第 4.3 条、第 13.5 条）：不同类型的实体用**不同的切工**，切面越多不等于越好 —— 形状要能一眼看出它是哪一类。颜色仍然只编码事实（类型），切工编码**语义族**；两者合起来，颜色从不单独承载事实（第 2.2 条、第 7 条）。
>
> 侘寂约束的是**用笔**与**克制**，不是**材质**：平面层仍然是墨描（第 14 章），三维里画的是石头。石头就该是石头。
>
> v3.8 变更：**三维要画出架构，不只是摆石头**（新增第 4.9 条「架构箭头」、第 13.6 条「产品架构阶段表」、第 13.7 条「箭头参数表」；第 12.4 条整条改写；第 9、10、11、13.4 条随之同步）。v3.7 把石头做成了真宝石，但场景里仍然只是「一堆石头加几根管子」—— 看得出材质，看不出**结构**。架构图之所以是架构图，靠的是**方向**：谁指向谁、谁在谁之前。因此这一版给三维加上一等公民——**箭头**：一条淡墨的细管、一枚墨色的小锥、一颗沿管行进的实心墨点。控制台的 SURFACE 从此不再是一盘按黄金角摆开的工具，而是**这个产品自己的架构**：五个阶段（入口与工作单 / 契约与词表 / 建立模型 / 校验与推演 / 产出与写入），每个阶段一种切工，阶段之间是动态箭头。
>
> 两条硬约束随之写进方针：① **手势仍是 Unity 的那九行**，控制台与两个公开场景共用 `unity-controls.js` 一份实现，谁都不许自己加键；② **产出件必须是同一套预设** —— 箭头模块与切工表住在共享运行时里，`gemarc_render` 交出去的固定件就带着它们，生成出来的站点与后台长得一样、手感一样。
>
> 一句话方针：**切面、墨线、真实的折射与反光、有方向的架构箭头；颜色只编码事实，不负责好看。**

## 2. 六条信条

1. **语义优先，装饰为零**：每一个可见元素都必须对应模型里的一个事实。无法对应事实的装饰一律不做。
2. **颜色是编码，不是修饰**：同一颜色在站点与三维场景里必须指同一件事。颜色永远配形状或文字，不单独承载事实。
3. **切面而不是阴影**：层级用 1px 棱线与底色差表达，不用多层投影堆出体积感。
4. **静者静，动者有度**：公开站点静止即静止（没有自转、没有呼吸、没有循环动画）；后台工具面允许缓慢律动，但律动**不得承载任何事实** —— 晶体的位置、颜色、数量仍然由事实决定（第 12.4 条）。
5. **可读性高于气质**：正文对比度不低于 4.5:1。任何「晶莹」处理不得压住文字与数据。
6. **简明高于完整**：界面用最少的字说清一件事。技术值、原始枚举、英文协议字段折叠到详情里，首屏不堆叠（第 12.6 条）。

## 4. 三维材质规则

### 4.1 几何

- **实体 = 被切割过的宝石**：多面体，不用球。球没有棱线，就不是宝石。
- **切工按类型分**：不同类型的实体用不同的切工（第 4.3 条），轮廓要能一眼区分；不得所有实体都长成同一个形状。
- **容器（楼/层/房间）= 线框**：只画棱线，不画实心体；楼层可有一块半透明底板。
- **关系 = 光线**：细管、半透明、未选中时更淡。信任边界一类用分段几何表示虚线，不得用贴图。

### 4.2 晶体主体与墨线

- 实体主体是**一块真的宝石**：`MeshPhysicalMaterial` —— `transmission: 0.9`（真折射：背后是什么，石头里就是什么）、`roughness ≤ 0.05`（磨光的刻面）、`metalness: 0`、`ior` 2.0–2.4（宝石的折射率）、`dispersion`（色散：白光在切面里散成彩边）、`thickness`（折射体积）、`attenuationColor` 取类型色（石头里透出的那一点颜色）、`clearcoat`（磨光的那层漆：刻面边缘那道锐利的白点）、`flatShading: true`（刻面级硬边）。参数表见第 13.1 条。
- **透射不取满**：宝石的亮主要来自**刻面把环境光反射回去**（耀光），不是来自把背景整个透过来。透射拉满，石头就成了一片染了色的玻璃片 —— 切面反而被洗掉了。
- **透明来自折射，不来自混色**：不再有不透明度区间，不再是半透明叠加，也不再画双面半透明。**石透、墨不透**依然成立 —— 但「透」是石头的物理性质，不是画法。
- 实体轮廓：**只留极细的外轮廓墨线**（第 4.8 条），颜色固定为 `--gem-ink`；内部的棱线**不画** —— 折射与刻面反光已经把它们表现出来了，再画一遍就成了线框模型。选中时墨线加粗一档，主体的颜色与几何都不变。
- 容器（楼/层/房间）仍是**线框**，关系仍是**细管**；线框与细管用 `--gem-rim` 一类的土色，不发光。
- **退避（focus）改的是墨线与反光，不是颜色也不是几何**：退下去的晶体墨线变淡、反光变弱，类型色与切工一个都不改（第 3 节：颜色仍然只编码事实）。

### 4.3 类型色板

三维实体按类型取色，未登记的类型使用统一的中性灰（不与任何已登记类型同色）。全部取自第 3.2 节五种颜料的浅/深档，CIELAB 彩度 C\* 一律 ≤ 50（实测最大 47.6）：

| 类型 | 颜色 | 类型 | 颜色 |
|---|---|---|---|
| system | `#3d5a72` | actor | `#b4654a` |
| service | `#96501f` | gateway | `#a9762f` |
| module | `#56663a` | plugin | `#6e7b45` |
| process | `#5f5573` | security | `#8a3a2c` |
| data | `#5a7566` | operations | `#7e8b93` |
| database | `#4c6e7a` | runtime | `#8c8271` |
| storage | `#6b5f7e` | external | `#8f8577` |

未登记类型：`#9c927f`（土・灰）。

**切工表（形状编码语义族）**：形状与颜色一起承载事实 —— 颜色说「是哪一类」，切工说「它扮演什么角色」：

| 切工 | 轮廓 | 语义 | 归入的类型 |
|---|---|---|---|
| 明亮式 brilliant | 圆明亮式：台面 + 冠部 + 尖底，十六面 | **枢纽**：整个模型的主干 | system、runtime |
| 柱式 column | 六棱柱：小台面、直身、尖底 | **承载**：对外提供能力 | service、gateway |
| 棱式 wedge | 八棱祖母绿式：阶梯肩、宽台面 | **边界**：数据的存与取 | data、database、storage |
| 阶式 step | 四棱阶式：宽底、阶梯肩、小台面 | **构成**：可拆可换的部件 | module、plugin |
| 锥式 pyramid | 三棱尖式：上下双尖 | **推进**：流程与运维 | process、operations |
| 橄榄式 marquise | 细长双锥（船形） | **行为者**：人或代理 | actor、external |
| 盾式 shield | 五棱盾式：宽肩、上下双尖 | **防护**：权限与校验 | security |
| 素石 plain | 原石正八面体（未切） | 未登记类型的中性形 | （未登记） |

- 每一种切工都是**真的切工**：上面有台面、中间有腰棱、下面有尖底 —— 没有平底平顶的「罐子形」。石头在轮廓上就该看得出是被切过的。
- 切工**只在这张表里变**：同一个类型在任何场景、任何产出件里都是同一个切工（第 13.5 条）。
- 切工是**几何**，不是装饰：它必须能被一眼区分，不得为同一族再私加变体。

### 4.4 坐标轴

- 三根轴各占一种颜料：X=`--gem-ai`（藍）、Y=`--gem-fuji`（藤）、Z=`--gem-kaki`（柿）。
- 每根轴画成一根光柱，刻度处有一道短横，刻度值是标签。
- **轴值是类别不是度量**：不得把顺序型数值伪装成可比较度量；一根轴只有一个取值时，必须显式报告「该轴不提供独立信息」。

### 4.5 灯光

- 一盏环境光 + 一盏主光 + 一盏**暖色**补光（纸面反弹光），比例约 0.75 / 0.55 / 0.25。**没有冷蓝补光**。
- **主光是摄影棚，不是这三盏灯**：石头被摄影棚照亮（刻面朝着亮条转过去，火彩就是这么来的），三盏灯只是**补光**（比例照旧，总量压到 0.55）。拧大了，类型色会被白色的漫反射洗掉，石头变成一颗粉笔头。
- 宝石的**反光**来自一个**程序化摄影棚环境**（第 13.1 条）：一间暖色暗室（`--gem-ink`）+ 一排**窄亮条**（亮条用纸白 `--gem-panel` 与 `--gem-facet`），烘成一张环境贴图。它不新增事实、不引入贴图文件，只给刻面一个可以反的「天」。
- 暗室里的亮条要**窄**：每一面刻面只接住**一条**亮条，所以面与面之间是硬边，石头才有火彩。宽泛的光盒会把石头洗成一片白。
- **曝光属于宝石，不属于纸**：曝光只抬石头（纸底是背景色，不吃曝光）。石头比纸暗是宝石的常态，但暗到看不清刻面就不叫宝石了。
- 公开场景的背景用 `--gem-bg`（纸）。禁止过曝光晕、禁止体积雾、禁止地面反射、禁止发光材质（`emissive` 恒为 0，只有后台工具面的呼吸律动例外，见第 12.4 条）。

### 4.6 三维禁止项（公开场景）

- ❌ 持续自转、呼吸缩放、粒子、拖尾。
- ❌ 彩虹渐变贴图、噪声贴图、扫描线。
- ❌ 用三维装饰承载模型里没有的事实（假楼层、假房间、假设备）。
- ❌ **发光**：自发光材质、霓虹边线、纯黑纯白的描边。
- ❌ **磨砂**：粗糙的、不透的主体（第 4.2 条：宝石是透明的；石头磨成砂就不叫宝石了）。
- ❌ **假反光**：用一层加色贴片、用自发光或霓虹边线冒充刻面的反光（第 4.7 条）。反光必须来自**真实材质**在**真实环境**里的反射。
- ❌ **假折射**：用半透明的平面色块假装石头里能看见后面（第 4.2 条）。

后台工具面的律动是第 12.4 条的**唯一**例外：它只改姿态与亮度，不改几何、布局与配色。

### 4.7 真实宝石材质（折射、色散、刻面反光）

一块石头看起来像宝石，靠的是三件事，而且必须是**真的**：

1. **折射**：光进入石头后拐弯，所以石头里能看见被折射过的背景。实现是 `transmission: 0.9` + `ior`（折射率）+ `thickness`（折射体积）。半透明的平面色块做不到 —— 它只是把底色调淡。
2. **色散**：白光在石头里按波长分开，边缘泛出彩边。实现是 `dispersion`。这是折射的副产品，不是贴图。
3. **刻面反光**：每一面只反射它自己朝向的那一小片环境，所以同一颗石头的不同面亮度不同，面与面之间是**硬边**。实现是低粗糙度 + 一张摄影棚环境贴图（第 4.5 条）+ `flatShading: true`。
4. **磨光的那层漆**：切面边缘那道锐利的白点是清漆层（`clearcoat`）给的，是材质真的一层，不是画上去的高光。

规则：

- **参数有上下限**：`transmission = 0.9`、`roughness ≤ 0.05`、`metalness = 0`、`ior` 2.0–2.4、`clearcoat = 1`；越界就成了塑料或玻璃砖（参数表见第 13.1 条）。
- **类型色进石头里，不涂在表面上**：`attenuationColor` 取类型色、`attenuationDistance` 决定色多深；表面不加色、不染色，石头的颜色只能来自石头内部。
- **硬边**：刻面与刻面之间是硬边，不得出现跨切面的连续渐变，不得出现柔边光斑。
- **不过曝**：反光的最亮来源是纸白 `--gem-panel`，不得出现纯白像素；不得发光（`emissive` 恒为 0，公开场景）。
- **不新增事实**：折射、色散、反光都只由已有的背景、已有的类型色与当前视角决定；不引入贴图文件、不写自定义着色器、不改主体的几何与位置。
- 反光与主体共用一份实现（第 13.4 条）：材质住在 `gem-material.js`，三个场景都从那里取，不得各写一份。

### 4.8 轮廓墨线（只留外缘）

- **墨线只画外轮廓**：石头的外缘有一道**极细**的墨线（常态 1 像素，选中 2 像素），颜色固定 `--gem-ink`。**内部的棱线不画** —— 棱线在折射里已经看得见，再画一遍就成了线框模型。
- 实现是**外扩一层反面壳**：同一份几何、放大一线、只画背面（`side: BackSide`）。壳只比石头大出那道线的宽度，所以墨线永远贴在外缘上，不会跑到石头里面去。
- **线的宽度按屏幕算**，不按世界算：同一道线在远近不同的晶体上一样细，放大场景时它不会变成一条粗边。
- 墨线**不参与拾取**：壳比石头大一点点，点在石头旁边的空白仍然是空白。
- 墨线是刻面与普通方块的区别。没有墨线的石头不是被切割过的结构。

### 4.9 架构箭头（方向是一等事实）

- **箭头画的是方向**：一条淡墨的细管 + 一枚墨色的小锥。没有方向的关系只是一根管子，看不出「谁在谁之前」，那就还不是架构图。
- 箭头只画在**真实存在的关系**之间（第 2.1 条）：模型里没有的关系不画，阶段之间没有真实流向也不画。
- **箭身是淡墨，箭头是墨**：管身取 `--gem-muted`（淡墨，与关系线同量级），锥头取 `--gem-ink`（墨）。箭身不发光、不透明成实体棒。**锥头不得用纸白** —— 场景的底就是纸色（`--gem-bg`），纸白的锥头落在纸上等于没画；同理，箭身也不能取纸白。
- **整个箭头都是线，不是实体**：箭身、锥头与行进点一律用透明墨画出（不透明成实体棒）。**理由是硬的**：三维引擎把不透明物体画进宝石的折射缓冲，不透明的锥头会被宝石自己折射进去 —— 那颗宝石会照着自己的箭头变黑。箭头一旦成了实体，就再也不是线了。
- **箭头停在石头表面**：关系画成箭头时，锥头落在目标石头的表面上，不埋进石头里（承接上条：埋进去就是折射缓冲里的黑点）。
- **行进点是几何**：一颗实心小球沿管走，周期固定（第 13.7 条），颜色是墨。它**不是**自发光、不是光晕、不是辉光贴图 —— 禁止项与第 8 条的自发光禁令同一条。它是「实心墨点」，不是「光点」：纸上没有光，只有墨。
- **持续行进只发生在后台工具面**（第 12.4 条）。公开三维场景里箭头是**静止**的：方向靠锥头表达，运动只在读者选中某条关系时出现（第 6 条、第 11.1 条：公开场景没有持续动画）。
- **语义轴场景的关系画成箭头**：模型里的关系本来就带方向，画成管子是把方向丢了。**楼/层/房间场景的关系仍是细管**：那是空间结构里的连线（含信任边界的虚线），不承载流程语义，箭头会替它说一件模型没有说的话。
- 箭头与宝石共用一份实现：几何、材质与参数住在 `flow-arrows.js`，三个场景与生成出来的产出件都从那里取（第 13.4 条）。

## 7. 可访问性

- 正文对比度 ≥ 4.5:1，次要文字 ≥ 3:1。
- 颜色不单独承载事实：状态永远是「颜色 + 形状/文字」。
- 所有可拖拽分隔条可聚焦、可键盘调节（当前宽度以 `aria` 数值属性或可见文字给出）。
- 三维拾取失败时必须显式说明，不得用二维图伪装三维。
- 持续律动必须尊重 `prefers-reduced-motion`：系统要求减少动效时，后台工具面**静止**。

## 8. 反面清单

- ❌ 磨砂压在数据表或代码块上；**任何**玻璃与背景光晕（侘寂是纸，不是玻璃）。
- ❌ 霓虹粉紫渐变铺底、彩虹色文字、纯黑纯白（**色板上没有这两个颜色**）。
- ❌ 公开三维场景的物件持续自转或呼吸。
- ❌ 用颜色承载事实、却没有形状或文字冗余。
- ❌ 圆角 + 多层投影堆叠出体积感。
- ❌ 为了「像宝石」而牺牲正文可读性。
- ❌ 三维场景自创一套与 Unity 不同的手势（见 §9）。
- ❌ 用第二套底色表达「浅色模式」（**只有一张色板**，见第 3 节）。
- ❌ 首屏把协议字段、枚举与原始值堆成一排标签（第 12.6 条）。
- ❌ 产出没有经过一次**整体** UI/UX 优化就交付（第 15 条）。
- ❌ 用模糊投影、渐变填充或噪声贴图做「漫画感」（第 14 条）。
- ❌ 让三维实体发光或用霓虹描边（第 4.6 条）。
- ❌ 用假反光（加色贴片、自发光、霓虹光边）冒充宝石的光泽（第 4.7 条：反光来自真实材质在真实环境里的反射）。
- ❌ 在石头内部画棱线（第 4.8 条：墨线只留外缘，内部的棱线交给折射）。

## 9. 三维操作与 Unity 一致

三维不只是「看起来像三维」，它也是一套**操作模型**。读者按 Unity 的肌肉记忆操作 GemArc 的三维场景时，必须得到同样的结果。因此凡是对三维模型的操作语义——相机、选择、框选、聚焦——一律以 Unity 2022.3 的场景视图为准；本站不发明第二套手势。

### 9.1 映射表（唯一口径）

| 操作 | 快捷键 | 作用 | Unity 对应 |
|---|---|---|---|
| 环绕 | Alt + 左键拖动 | 绕枢轴旋转视角 | Alt + Left Mouse Drag |
| 平移 | 中键拖动 | 枢轴随视线平行移动 | Middle Mouse Drag |
| 飞行 | 右键拖动 | 相机自由飞行，用 W/A/S/D 与 Q/E 移动 | Right Mouse Drag |
| 推拉 | 滚轮 | 镜头沿视线推近或拉远 | Mouse Wheel |
| 选择 | 左键点击 | 选中指针下的实体或关系 | Left Mouse Click |
| 加选 | Ctrl + 左键点击 | 把目标加入选择，或从选择中移除 | Ctrl + Left Mouse Click |
| 框选 | 左键在空白处拖动 | 选中矩形内的全部目标 | Left Mouse Drag on empty space |
| 清空 | 左键点击空白处或 Esc | 清空当前选择 | Left Mouse Click on empty space / Esc |
| 聚焦 | F | 把视角对准当前选择 | F (Frame Selected) |

这张表在代码里**只有一份**：`scaffold/runtime/space/unity-controls.js` 的 `UNITY_CONTROL_MAP`。页面上的操作提示、本节这张表和代码由同一条测试绑定；改一处而漏掉另一处会被门禁拦下。

### 9.2 语义细则

- **左键只做选择**。左键拖动不再旋转视角：拖到空白处是框选，拖在目标上什么也不发生。这既与 Unity 一致，也根除了「想点选却把场景转跑了」这一类误操作。
- **修饰键优先于模式**：Alt 让左键变成环绕，Ctrl 让左键变成加选；两者不同时生效。
- **按下与拖动由位移区分**：位移小于 5 像素算点击，大于等于 5 像素算拖动。判定只看位移，不看按钮——这是「点得中」与「转得动」能同时成立的前提。
- **选择状态只有一份**：三维场景不自己保存选择，选择住在跨视图状态里，因此二维图与三维场景永远一致。
- **框选按位置判定**：实体落在矩形内即被选中；关系要两端都在矩形内才算被选中——半条关系不是关系。
- **F 聚焦选中**：有选中时对准选中，没有选中时对准整个场景。
- **点击空白处与 Esc 都清空选择**。

### 9.3 与宝石主题的关系

- 宝石色板不变：颜色仍然只编码事实（类型、轴、状态），不编码操作。
- Unity 式红/绿/蓝只允许出现在**操作提示元素**类元素上（例如框选矩形的边），不得改写实体颜色，也不得取代「选中 = 墨线加粗」这条规则。
- 三维操作提示以一行小字放在画布下方，字号与次要文字一致，不喧宾夺主。

## 11. 验收口径

一条产出算「符合本方针」，当且仅当：

1. **公开**三维场景里**没有**持续动画，实体**有**可见墨线，关系是细管而不是实心杆；
2. 场景背景与界面底色都是纸（`--gem-bg`），实体是**真宝石**（折射 + 色散 + 刻面反光，第 4.2、4.7 条）+ **极细的外轮廓墨线**（第 4.8 条），**没有**发光、磨砂与假反光；
3. 页面上每一种强调色都能对应到「可交互」或「当前选中」之一；
4. 正文没有任何一处压在半透明层上；
5. 同一个模型渲染两次，场景**逐像素一致**（确定性是宝石主题的一部分：同一颗宝石，切面必须一样）；
6. §9.1 的九行手势逐条可复现：左键点击选中、点击空白清空、Ctrl 加选、拖动框选、Alt 环绕、中键平移、右键飞行、滚轮推拉、F 聚焦、Esc 清空；
7. 两个三维场景（语义轴、楼/层/房间）对同一套手势的反应**完全一致**；
8. **后台工具面**的律动只改姿态与亮度：同一份工具表，几何、位置与配色逐个不变（律动的帧本身不参与第 5 条的逐像素比对）。
9. **后台三个界面与工具描述都是三语**：`zh-CN` / `ja-JP` / `en-US` 三张表键集合相同；切换语言只改文字，不改事实、ID、协议字段与证据状态；取不到键时显示键本身并记一条缺口。
10. **平面层带着第 14 条的和紙墨描**：结构元素有明确墨线，面是平涂，需要浮起感的地方是硬边偏移影而不是模糊投影，纸底有纤维质地，分格之间有留白；**产出经过了一次整体 UI/UX 优化**，且最终说明里写了这一轮做了什么（第 15 条）。
11. **第 16 条的五条硬约束全部成立**：色板里没有纯黑纯白、彩度在上限内、纸的三个面明度相邻、强调色面积不超过 5%、正文与控件的对比度达下限。
12. **石头是石头**：折射看得见背后的纸、色散在边缘散出彩边、刻面上有一道锐利的反光、抛光层在刻面边缘点出一道白（第 4.7 条）—— 不是一片染了色的纸片，也不是一层假高光贴上去。
13. **形状与颜色一起承载事实**：每种类型都有固定的切工（第 4.3 条、第 13.5 条），三个场景对同一类型给同一个形状与同一种颜色；墨线只在外缘，石头内部没有多余的棱线（第 4.8 条）。
14. **三维画得出架构**：关系有方向（箭头，第 4.9 条）；控制台的 SURFACE 呈现**产品自己的架构**（阶段分组 + 每阶段一种切工 + 阶段之间的动态箭头，第 12.4、13.6 条）；**手势与快捷键就是 Unity 的那九行**，三个场景共用一份实现（第 9.1 条）；**产出件的固定件预置同一套** —— 生成出来的站点带着同样的切工、箭头与手势（第 13.4 条）。

## 12. 后台界面（控制台、账号页、运营区）

后台 = 三个界面：MCP 控制台（`/`）、账号页（`/account`）、运营区（`/account/admin`）。它们与公开站点是**同一个产品**，画风必须一致 —— 站点与后台现在都是**同一张纸**。

### 12.1 色板只有一个来源

- 后台**共用第 3 节登记的全部 `--gem-*` 令牌**（纸与墨 3.1 + 顔料 3.2），不得另起一套近似色（例如「另一组 `--bg/--panel/--accent`」）。同名不同义、同义不同名都不允许。
- 后台若需要一个色板之外的语义色，先在第 3 节登记它，再在代码里使用它。

### 12.2 界面语言：和紙

- 后台是**浅色单主题**：账号页与运营区不随系统的深色偏好切换（`color-scheme` 固定为 light）。
- 页面底是 `--gem-bg`（生成り和紙）+ 纸纤维底纹；**没有玻璃层、没有背景光晕、没有背景模糊**（第 8 节：侘寂是纸，不是玻璃）。
- 三维画布与公开场景同一张纸（`--gem-bg`）。
- 正文用 `--gem-ink` / `--gem-muted`；强调用五种颜料。
- 卡片 = `--gem-panel` 或 `--gem-facet` 实底 + 1px `--gem-muted` 边 + 极轻内高光；数据表、代码块、JSON 结果一律实底。
- 圆角统一 6px（小控件 4px），大块面板 8px —— 与公开站点一致，不再为玻璃质感放宽到 10px。

### 12.3 「事实」在后台指运行态事实

第 2.1 条的「事实」在后台不是模型字段，而是**服务端的运行态事实**：注册的工具、资源、提示词、账号、审计条目、开关取值、部署状态。

因此：

- 后台的界面元素只要对应上面这些事实之一，就是合规的；反之（画一个不存在的楼层、不存在的设备、不存在的工具）一律禁止。
- **品牌标记**（GemArc 的晶体标志）承载品牌而不是事实：它只允许出现在标题区与站点标识位置，不得动画、不得承载交互语义，也不得当成数据。
- 控制台的三维场景**必须**由运行态事实生成：第 13 条的材质规则对它同样成立，它画的每一个晶体都对应一个真实注册的工具。

### 12.4 后台三维场景（控制台）：画出产品自己的架构

- 控制台提供一块**可交互**的三维晶体场景，承载服务器的**工具面**。它画的是**这个产品自己的架构**，不是一盘按角度摆开的工具：工具按它在流程里的**阶段**分成五组（第 13.6 条），阶段之间是**动态箭头**（第 4.9 条）。
- **每个注册的工具一颗晶体**：没有注册工具就没有晶体，不得画占位晶体充数。未登记在阶段表里的工具归入「其余」一组，用**素石**（plain）。
- **阶段决定切工**：同一阶段的工具是同一种切工，切工编码的是这一阶段的**角色**（第 4.3 条、第 13.6 条）；同一个工具在任何场景里都必须是同一个几何（第 13.5 条）。
- **颜色仍然只编码运行态事实**：只读晶体 = `--gem-ai`（藍），写入晶体 = `--gem-kaki`（柿），两种色取自色板，场景旁必须有同样的图例文字。颜色不承载阶段语义。
- **箭头只连真实存在的阶段**：只有当相邻的两个阶段都真的有注册工具时，它们之间才画一根箭头；箭头上有一颗沿管行进的墨点（第 4.9 条）。
- 布局是**确定的**：同一份工具表渲染两次，晶体与箭头的位置逐个相同（承接第 11.5 条）。
- 材质、切工、箭头与手势都来自**共享模块**：控制台场景导入 `gem-material.js`、`flow-arrows.js`、`product-architecture.js` 与 `unity-controls.js`，不另写一份（承接第 13.4 条）。
- 拾取一颗晶体 = 选中那个工具（与二维工具列表同一份选择状态，一处变另一处跟着变）。
- **手势沿用第 9.1 节的九行映射**，与两个公开场景共用同一份实现；控制台**不得**自己再加键或改键。
- 三维不可用时（没有 WebGL、脚本没有取到三维库）面板**如实说明「未加载」**，控制台的其余功能照旧可用；不得用一张图片假装三维。
- **律动**：晶体缓慢自转，亮度随时间呼吸（周期约 6 秒，自转一周约 60 秒），箭头上的墨点沿管行进（周期约 2.6 秒）。律动只改姿态、亮度与墨点的位置，**不改几何、位置与配色**（第 11.8 条）。
- 律动必须可关：系统开启「减少动效」（`prefers-reduced-motion: reduce`）时，场景静止（箭头保留方向、去掉行进），只保留读者操作引起的变化。

### 12.5 可访问性不变

- 正文对比度 ≥ 4.5:1，次要文字 ≥ 3:1。
- 颜色不单独承载事实：状态永远是「颜色 + 形状/文字」。
- 后台的表格与表单在窄视口下允许换行与横向滚动，但**不得**为了「像宝石」而删掉字段、截断可读性或把关键操作藏进悬停。

### 12.6 信息密度

- **首屏状态行不超过 5 个要点**，且每个要点是一个短语，不是一个键值对。协议路径、传输方式、工具集这类技术值**折叠到详情**，不占首屏。
- 状态用**当前语言**的短语（中文：「工具 9」「只读」「站点未构建」；日文与英文同理），原始英文值放进详情或页脚。
- 一次只回答一个问题：面板顶部回答「服务器是什么状态」，工具区回答「我能调什么」，舞台回答「这一个工具怎么用」。
- 错误提示一句话说完，不重复、不追加解释性长句。

### 12.7 语言切换

- 后台三个界面（控制台、账号页、运营区）与 **MCP 工具描述**都提供三语：`zh-CN` / `ja-JP` / `en-US`。文字的**唯一来源**是 `src/gemarc_mcp/i18n/<locale>.json`，三张表的键集合必须相同。
- **选择顺序**：本机记住的选择 → 浏览器语言（`Accept-Language` / `navigator.language`）→ `zh-CN`。
- 切换只改**显示文字**：模型 ID、工具名、参数名、协议字段、证据状态一律不变（第 2.1 条、第 12.3 条）。
- 切换器是**一行三个选项**，放在页头；每个选项用**自己的语言**写自己（「中文」「日本語」「English」），不用语言代码当标签。
- 切换不改变布局：首屏仍不超过 5 个要点（第 12.6 条），三语的要点条数相同。
- 控制台有脚本，语言选择记在**本机**（`localStorage`），不写进 URL；账号页与运营区**没有脚本**，语言切换用链接（`?lang=`）并记在 Cookie 里。
- **缺键不得静默混语**：取不到键时显示键本身，并记一条缺口；三张表键集合不一致就是缺陷，不是可接受状态。

### 12.8 会话与登出

- 控制台右上角有**登出**按钮，与**会话**同生死：没有会话（只有 MCP 令牌）时**不出现**。
- 登出是**带 CSRF 令牌的 POST 表单**，不是链接：没有脚本也能用，链接也永远不会触发它。
- 文案与账号页一致（登出 / サインアウト / Sign out）：同一件事只有一个名字。
- 它排在语言切换器与「设置」之后，并**用一条细线**与「设置」分开：结束会话是一个边界，不是又一个设置。

## 13. 宝石材质（真实质感）

三维里画的是**石头**，不是石头的样子。石头之所以是石头，靠的是折射、色散与刻面反光（第 4.7 条）；侘寂约束的是**用笔**与**克制**，不是材质 —— 平面层仍然是墨描（第 14 章）。

### 13.1 真实材质（参数表）

三维的石头是**物理材质**（`MeshPhysicalMaterial`），参数只有这一张表：

| 参数 | 取值 | 为什么 |
|---|---|---|
| `transmission` | `0.9` | 折射：背后是什么，石头里就是什么。不取满 —— 宝石的亮在刻面反光上，透满就成了染色的玻璃片（第 4.7 条） |
| `roughness` | `0.03` | 磨光的刻面；越粗糙越像塑料 |
| `metalness` | `0` | 石头不是金属 |
| `ior` | `2.2` | 宝石的折射率（钻石 2.42、蓝宝石 1.77） |
| `dispersion` | `1.5` | 色散：边缘的彩边 |
| `thickness` | 石头半径 × 0.85 | 折射体积：石头越厚，透过去的越少 |
| `attenuationColor` | 类型色 | 石头内部透出的那一点颜色 |
| `attenuationDistance` | 石头半径 × 2.2 | 色多深 |
| `envMapIntensity` | `4.5` | 刻面反光的强度 |
| `clearcoat` | `1` | 磨光的那层漆：刻面边缘那道锐利的白点 |
| `clearcoatRoughness` | `0.03` | 漆是抛光的，白点必须是点，不能是一片 |
| `flatShading` | `true` | 刻面级硬边 |
| `side` | `DoubleSide` | 看得见自己的内刻面 |
| `toneMappingExposure` | `1.6` | 曝光：石头比纸暗，这是宝石，不是石头；纸底不吃曝光（它是背景色） |
| 场景灯比例 | `0.75 / 0.55 / 0.25` × `0.55` | **摄影棚才是主光**；这三盏只是补光，拧大了会把类型色洗白 |

- 参数**是常量**：不随实体、不随选中状态变化，因此同一模型两次渲染逐像素一致（承接第 11.5 条）。
- `thickness` 与 `attenuationDistance` **跟着石头的大小走**：两个场景的石头大小不同，但比例一致，所以观感一致。
- 唯一允许随时间变化的是自发光（后台工具面的呼吸辉光，第 12.4 条）：它不引入新的贴图与着色器，也不改几何。
- 反光需要一个**环境**：一间暖色暗室（`--gem-ink`）加一排窄的纸白亮条（`--gem-panel` / `--gem-facet`），用 PMREM 烘成环境贴图（第 4.5 条）。它由代码生成，不引入贴图文件。
- 亮条要**窄**：刻面只接住一条亮条，面与面之间才是硬边，石头才有火彩。

### 13.2 墨线

- **墨线只画外轮廓**（第 4.8 条）：外缘一道极细的墨线（常态 1 像素、选中 2 像素），**内部的棱线不画** —— 棱线在折射里已经看得见。
- 实现是**外扩一层反面壳**：同一份几何、放大一线、只画背面；宽度**按屏幕算**，所以远近的晶体一样细。
- 墨线颜色**固定为 `--gem-ink`**（墨）：不是主体色的提亮 —— 提亮的边是宝石的画法。
- 不得叠加屏幕空间描边或后期描边：边来自它被切割过本身。

### 13.3 禁止项（与第 4.6 节并列）

- ❌ 连续渐变阴影（未量化的 PBR 高光）。**例外只有一处**：刻面本身是平的，面与面之间是硬边（第 4.7 条）。
- ❌ 体积雾、地面反射、过曝。
- ❌ 半调网点、扫描线、材质噪声贴图、彩虹渐变。
- ❌ 公开场景里的自转、呼吸缩放、粒子、拖尾。
- ❌ 不透明的主体、自发光材质、霓虹描边。
- ❌ **假反光**：加色的高光贴片、假的镜面层、把石头内部画成棱线（第 4.6、4.7、4.8 条）。

允许（仅后台工具面）：材质自发光强度随时间缓慢变化，形成呼吸辉光。它**不得**引入新的贴图、新的着色器或改变石头的几何 —— 呼吸辉光只是自发光强度的变化。

### 13.4 只有一份实现

- 宝石的材质实现住在**一个模块**里，两个公开场景与控制台的后台场景都用它。三处各写一份必然漂移，绑定测试会拦住这种漂移。
- 材质模块不依赖任何三维库的具体版本细节，只使用「材质类 + 几何类 + 环境烘焙」这几个标准接口。
- **箭头与产品架构表同样只有一份**：`flow-arrows.js`（箭头几何与行进）与 `product-architecture.js`（阶段与切工）住在共享运行时里，**产出件的固定件也带着它们**（第 12.4 条）—— 生成出来的站点与后台因此是同一套预设：同样的宝石、同样的切工、同样的箭头、同样的 Unity 手势。

### 13.5 切工编码语义

- 切工表在第 4.3 条：**每种类型一个固定的切工**，轮廓要能一眼区分。
- 实现只有一处：`gem-material.js` 的切工表与几何构造，三个场景都从那里取（承接第 13.4 条）。同一类型在三个场景里必须是**同一个几何**，不得各写一份近似形状。
- 切工**不是装饰**：它编码语义族，颜色编码具体类型；两者合起来，颜色从不单独承载事实（第 2.2 条、第 7 条）。
- 切工**不随状态变**：选中、退避、悬停都只改墨线与反光，不改切工（第 4.2 条）。

### 13.6 产品架构阶段表

控制台的 SURFACE 画的是**这个产品自己的架构**（第 12.4 条）。阶段表如下，代码里只有一份：`product-architecture.js` 的 `PRODUCT_ARCHITECTURE_STAGES`。

| 阶段 | 切工 | 工具 | 这一阶段做什么 |
|---|---|---|---|
| 入口与工作单 | 棱式 wedge | `gemarc_media_doc_guide`、`gemarc_brief` | 边界：先读流程，再拿工作单 |
| 契约与词表 | 柱式 column | `gemarc_contracts`、`gemarc_assets`、`gemarc_inspect`、`gemarc_plan` | 承载：规则、词表与事实来源 |
| 建立模型 | 明亮式 brilliant | `gemarc_new_model`、`gemarc_scaffold`、`gemarc_init` | 枢纽：模型的主干在这里长出来 |
| 校验与推演 | 盾式 shield | `gemarc_validate`、`gemarc_simulate`、`gemarc_diff`、`gemarc_verify` | 防护：校验、规则推演与对照 |
| 产出与写入 | 锥式 pyramid | `gemarc_render`、`gemarc_build`、`gemarc_export`、`gemarc_model` | 推进：把产物交出去，或写回工作区 |

- 阶段是**流程的事实**（承接第 2.1 条）：阶段表与服务端 `gemarc_brief` 的流程段（`service.py` 的 `procedure`）说的是同一件事，两边不得各说一套。
- 阶段之间是**线性流**：入口 → 契约 → 建模 → 校验 → 产出，相邻两阶段之间各一根箭头（第 4.9 条）。
- 阶段表覆盖**全部 17 个工具**（无状态 9 个 + 工作区 8 个）；服务端注册了哪些就画哪些，没注册的不画。
- 未登记的工具归入「其余」一组，用**素石**（plain），且不改变已登记工具的位置。

### 13.7 箭头参数表

| 参数 | 取值 | 为什么 |
|---|---|---|
| 箭身半径 | `0.2` | 与关系线同量级：箭头是线，不是棒 |
| 锥头半径 / 长度 | `0.8` / `2.2` | 墨色的小锥，一眼看出方向 |
| 行进点半径 | `0.5` | 比箭身粗得多，走过去看得见 |
| 行进周期 | `2.6` 秒 | 一圈 2.6 秒：看得出是「流」，又不晃眼 |
| 抬升（弓高） | `3.0` | 箭身从两个阶段之间拱过去，不穿过晶体 |
| 管段数 / 截面段数 | `40` / `8` | 弯的箭身要够圆，又不能太重 |

- 参数是**常量**：不随实体、不随选中状态变化，因此同一模型两次渲染逐像素一致（承接第 11.5 条）。
- 行进点的行进是**位置**的变化，不是材质的变化：不引入自发光、不改颜色（第 4.9 条、第 13.3 条）。

## 14. 平面层的和紙墨描渲染

第 13 章说的是三维里的石头。平面外壳此前只有「切面 + 亮棱」，没有**用笔**；本章补上：平面层用同一套墨描语言，纸面仍是底子。

一句话：**平涂 + 明确墨线 + 硬边偏移影 + 分格 + 和紙纤维**，颜色仍然只编码事实。

> v3.4 变更：原「美漫卡通渲染」的材料按侘寂改写 —— 墨线由**亮棱**改为**墨**（暗），硬边阴影仍是硬边但落在**纸上**，半调网点改为**和紙纤维**。

### 14.1 墨线

- 墨线是元素**自己的边**，不是后期叠加的轮廓（承接第 13.2 条：边来自它被切割过）。
- 平面层的墨线用 `--gem-muted`（淡墨 2px），主内容格用 `--gem-ink`（墨 3px）；**不是** `--gem-rim` —— 那是棱线与分隔条的弱一档。
- 控件与徽记（按钮、标签、芯片）用 1px 的边：它们不是结构件。可交互的控件用 `--gem-muted` 或 `--gem-ai`（第 16.2 条第 5 项：边界要看得见），纯徽记可以用弱一档的 `--gem-rim`。

### 14.2 平涂

- 面是纯色：不用渐变填充，不用背景图。

### 14.3 硬边阴影

- 需要浮起感的结构元素用**硬边**偏移影：偏移 3–4px、模糊半径 0、颜色 `--gem-void`（深一层的纸，像纸叠在纸上）。
- 只有一层，不堆叠（第 5 条）。

### 14.4 分格与标题框

- 主内容按「格」组织：每个维度视图是一格，格与格之间留白（侘寂的「間」）。
- 主内容格的墨线最重（`--gem-ink` 3px），其余格 2px `--gem-muted`。
- 面板标题是一枚**标题框**：实色底 `--gem-facet` + 2px 墨线 + 硬边阴影。

### 14.5 和紙纤维

- 页面底允许一层**极稀疏**的纤维底纹（CSS 细线，不是贴图、不是噪声）：这是和紙的质地。
- 纤维**不承载任何事实**，所以本条是第 2.1 条「装饰为零」的**唯一例外** —— 与第 12.3 条的品牌标记同理：它承载的是画风，不是信息。
- 纤维不得盖住正文与数据（第 7 条）：正文永远压在实底上。
- **禁止半调网点**（美漫印刷的机器纹）与噪点：纸的质地是纤维，不是网点。

### 14.6 克制

- 沿用第 1 条：光要克制。墨线变重不等于高光变多。
- 低彩度的颜料只出现在边框、图标、轴、状态点上（第 3.2 条）。

### 14.7 禁止项

- ❌ 模糊投影、多层投影堆叠、渐变填充、渐变文字、彩虹色、霓虹粉紫铺底。
- ❌ 半调网点、噪点、扫描线、材质噪声贴图（承接第 13.3 条）；三维场景仍然不准加任何贴图。
- ❌ 用颜色做装饰来暗示事实（第 2.1 条）。
- ❌ 墨线压住文字：描边不能盖住正文与数据（第 7 条）。

### 14.8 后台适用本章

后台与公开站点是同一张纸（12.2），因此本章的墨线、硬边偏移影、和紙纤维与标题框**同样适用于后台**；后台不再有玻璃外壳与光晕。

## 15. 产出必须经过一次整体 UI/UX 优化（硬约束）

### 15.1 硬约束

- 每一份产出**至少**做一次**整体** UI/UX 优化。这不是审美偏好，是可核对的要求。
- 「整体」的意思：不是逐项打勾的零碎修补，而是对整个产出做一遍**统一复核**，确认全站只有一套视觉语言 —— 同一个墨线口径、同一个分格节奏、同一个主次层级。
- 风格基准是本方针：和紙墨描的宝石主题（第 14、16 条）。
- 这一轮**不能省**，也不能只做其中一项就算数。

### 15.2 固定件预置主题，降低成本

- 固定件（外壳、共用运行时）已经把这一版主题做好了，随包发布，产出**开箱即带**和紙墨描的宝石主题。
- 所以这一轮优化**不是**从零做主题，而是**核对与落地**：主内容是否第一眼就突出、次级信息是否折叠、层次是否用模型的槽位表达、必要时用外壳的专注开关核对主区是否够大。
- 预置主题是为了降低使用者的优化成本，**不是**把这一轮变成可选项。

### 15.3 必须写进最终说明

最终说明里要有这一轮的记录：改了哪一处、依据哪一条、怎么核对的（打开了什么、看到了什么）。没有记录的产出不算完成这一轮。

## 16. 侘寂配色：依据与硬约束（v3.4 新增）

第 3 节的色板不是「挑好看的」，是**按可说的理由挑的**。本章把理由写下来，并把其中可测的部分变成硬约束 —— 好看是一次性的，约束是长期的。

### 16.1 五个颜料为什么是这五个

| 颜料 | 出处 | 色彩心理学上的作用 | 本产品里的语义 |
|---|---|---|---|
| 藍 `#3d5a72` | 藍染（日本传统的染料色） | 蓝紫色系**降低唤醒度**，在长篇阅读与技术文档里最不疲劳；深而不闷，是「可点」这类高频信号的稳妥色 | 可交互、当前选中、坐标轴 X |
| 藤 `#5f5573` | 紫藤 | 低彩度的紫天然读作「次要、辅助」；与藍同属冷色系，弱对比，适合承托而不抢戏 | 次强调、坐标轴 Y、辅助序列 |
| 柿 `#96501f` | 熟柿 | 橙红**提升亲和与注意触发**，但高彩度橙会制造焦虑 —— 所以取熟透的深赭：留住暖，去掉刺 | 坐标轴 Z、提示 |
| 苔 `#56663a` | 苔（缓生之物） | 绿是公认最不疲劳的色；「苔」意味着缓慢、稳定、不张扬 ⇒ 配「已确认」正好 | 已确认、正常、通过 |
| 錆 `#8a3a2c` | 铁锈 | 「红＝错误」的语义不必改，但鲜红在纸面上过于警报化；铁锈红保留警示、降低攻击性 | 错误、阻断、越界 |

纸与墨同理：**生成り**（未漂白的和纸，暖黄白 `#ebe1ce`）比纯白少一分刺眼；**墨**（暖炭 `#2e2a24`）比纯黑多一分笔触感 —— 纯黑在屏幕上读作「洞」，暖墨读作「写下来的字」。**中性色一律带暖色相**，这是「纸」的物理事实：纸不是中性的。

### 16.2 五条硬约束（可核对）

每一条都写成**可以用尺子量**的样子：给了量法、给了上限、给了实测值。量法写在这里，绑定测试按同一把尺子量色板（`tests/test_three_d.py` 的「第 16 条硬约束」一组用例）。

1. **无纯黑纯白，中性色一律带暖色相**：色板里没有 `#000000` / `#ffffff`；七个中性色（`--gem-void` / `--gem-bg` / `--gem-panel` / `--gem-facet` / `--gem-rim` / `--gem-ink` / `--gem-muted`）的 **HSL 色相**落在 **25°–45°**（实测 34.6°–40.9°）—— 纸不是中性的。反光的最亮来源取 `--gem-panel`（纸白），摄影棚的暗室取 `--gem-ink`，两者都在色板之内（第 4.5、4.7 条）。
2. **彩度上限用 CIELAB 的 C\* 量**（不用 HSL 彩度：淡色相在 HSL 里会被算得很艳 —— 本色板的纸面 HSL 彩度高达 48.8%，那是公式的错觉，不是纸发艳）：
   - 五种颜料 C\* ≤ **50**（实测 藍 17.4、藤 18.9、苔 27.0、錆 41.7、柿 47.6）；
   - 三维类型色板 C\* ≤ **50**（实测最大 47.6）；
   - 纸的三面（`--gem-bg` / `--gem-panel` / `--gem-facet`）C\* ≤ **12**（实测 10.5 / 7.6 / 11.4）。
   - **真实宝石不破这条上限**：石头内部的颜色来自 `attenuationColor`（类型色），刻面上的反光来自纸白 —— 两者的彩度都不高于各自的颜料，所以三维宝石在屏幕上的实际颜色永远不比它的颜料更艳。
3. **明度邻近用 CIELAB 的 L\* 量**：纸的三面两两 L\* 差 ≤ **8**（实测 89.9 / 93.9 / 87.5，极差 6.4；换成 HSL 明度也是 7.6%）—— 侘寂的层次来自**材质**，不来自强对比。
4. **强调色面积 ≤ 5%**：任何一屏里强调色的合计面积不超过 5%。低彩度不是让它到处出现的理由。
5. **对比度下限（WCAG）**：正文 ≥ **4.5:1**（`--gem-ink` 11.00、`--gem-muted` 4.53）；次要文字与**可交互控件的边界** ≥ **3:1**。因此纸面上的控件边界用 `--gem-muted`（4.53:1）或 `--gem-ai`（5.58:1），**不用** `--gem-rim`（只有 2.14:1 —— 那是分隔条与装饰边的弱一档）。五种颜料在纸面上的对比度分别是 5.58 / 5.34 / 4.67 / 4.82 / 5.95，都过正文线。

### 16.3 纸的质地

- 页面底 = `--gem-bg` 纯色 + **和紙纤维**（第 14.5 条）：两层极淡的斜向细线，不承载事实。
- 卡片与面板之间靠**纸的深浅**（`--gem-panel` / `--gem-facet`）与 1px 棱线分层，不靠投影堆叠，也不靠玻璃。
- 硬边偏移影仍在（第 14.3 条），但落点是**深一层的纸**（`--gem-void`）：像一张纸叠在另一张纸上，而不是像光打在物体上。

### 16.4 产出成果与产品同源

- **用户拿到的产出件**（多媒体文档站点）用的是同一张色板：三维实体的类型色（第 4.3 节）取自同样五种颜料的深浅档；三维场景的背景是同一张纸。
- **产出件里的石头与产品里的石头是同一种石头**：一样是真宝石（折射、色散、刻面反光，第 4.2、4.7 条），一样的切工（第 4.3 条），一样只有一道极细的外缘墨线（第 4.8 条）。产出件与产品不只在色板上同源，在**材质**与**形状**上也同源。
- 站点、三维场景、后台与产出件**没有第二套皮**：任何一处出现近似色，都是缺陷。

### 16.5 代价（诚实的取舍）

- 纸面比暗场**更吃对比度**：暗底上霓虹色很醒目，纸面上同样的彩度会「糊」掉 —— 这就是彩度上限与 5% 面积上限的由来。
- 层级比暗场**更依赖棱线**：暗场可以用亮度分层，纸上只能靠 1px 墨线与纸的深浅 —— 所以第 5 条的 1px 棱线是硬要求，不是装饰。
- **可交互性变弱**：淡墨线在纸上的存在感低于亮棱线在暗场上的存在感，所以控件边界一律用 `--gem-muted`/`--gem-ai`（第 16.2 条第 5 项），而不是 `--gem-rim`。
