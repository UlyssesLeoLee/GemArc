## 1. 立意：宝石是被切割过的结构

GemArc 的名字里有一个 Gem。宝石之所以是宝石，不是因为它有颜色，而是因为它**被切割过**：它同时具备秩序（对称的面）与光（棱线上的高光）。所以本方针不是「把界面做成宝石的样子」，而是：

- **界面像切面**：信息被切成边界清楚的面，面与面之间是棱线，不是阴影堆叠。
- **三维像晶体**：实体是被打磨过的半透明晶体，棱线比晶体主体亮；关系是穿过它们的光线。
- **光要克制**：宝石的美来自暗场里一小片高光。大面积高光会让水晶变成塑料。
- **后台是通透的水晶**：公开站点是暗场里的展柜，后台是白天里的玻璃柜 —— 同一批晶体，换一种光。

一句话方针：**暗场或亮场都可以，但切面、亮棱、少量高光不变；颜色只编码事实，不负责好看。**

## 2. 六条信条

1. **语义优先，装饰为零**：每一个可见元素都必须对应模型里的一个事实。无法对应事实的装饰一律不做。
2. **颜色是编码，不是修饰**：同一颜色在站点与三维场景里必须指同一件事。颜色永远配形状或文字，不单独承载事实。
3. **切面而不是阴影**：层级用 1px 亮棱线与底色差表达，不用多层投影堆出体积感（后台的玻璃外壳有唯一的例外，见 12.2）。
4. **静者静，动者有度**：公开站点静止即静止（没有自转、没有呼吸、没有循环动画）；后台工具面允许缓慢律动，但律动**不得承载任何事实** —— 晶体的位置、颜色、数量仍然由事实决定（第 12.4 条）。
5. **可读性高于气质**：正文对比度不低于 4.5:1。任何「晶莹」处理不得压住文字与数据。
6. **简明高于完整**：界面用最少的字说清一件事。技术值、原始枚举、英文协议字段折叠到详情里，首屏不堆叠（第 12.6 条）。

## 3. 色板（唯一色源）

站点与三维场景共用同一组令牌。令牌名写在 CSS 变量里，三维场景在 JavaScript 里使用同名常量。

**令牌名只允许小写字母、数字与连字符；值一律写成 6 位十六进制。** 后台多出来的浅底色板（第 3.2 节）同样是「唯一色源」的一部分 —— 后台不是另一个产品的皮肤。

### 3.1 深底色板（公开站点与三维场景）

| 令牌 | 值 | 用途 | 禁止 |
|---|---|---|---|
| `--gem-void` | `#06090e` | 最暗的底色（三维场景背景、页面外缘） | — |
| `--gem-bg` | `#0b0f16` | 页面底色 | — |
| `--gem-panel` | `#111823` | 面板、顶栏、检查器底 | — |
| `--gem-facet` | `#1b2635` | 卡片底、分隔面 | 承载正文 |
| `--gem-rim` | `#2c3d52` | 棱线、边框、分隔条 | — |
| `--gem-ink` | `#e6eef7` | 正文 | — |
| `--gem-muted` | `#93a6bd` | 次要文字、注释 | 承载正文 |
| `--gem-aqua` | `#6fe3ff` | 主强调：可交互、当前选中、坐标轴 X | 大面积背景承载文字 |

### 3.2 浅底色板（后台）

后台是浅色的玻璃柜：同一批晶体换一种光，但**颜色仍然只编码事实**。因此浅底的强调色不是新的一套色，而是**深底强调色同一色相的深档** —— 同一个语义，两种明度。

| 令牌 | 值 | 用途 | 禁止 |
|---|---|---|---|
| `--gem-air` | `#e9eff8` | 后台页面底：雾蓝白的空气层 | — |
| `--gem-sheen` | `#ffffff` | 玻璃面本色（透明度在用法里给，不写进令牌） | 承载正文 |
| `--gem-halo-aqua` | `#c9ecf7` | 背景光晕·水青 | 承载正文 |
| `--gem-halo-violet` | `#ded3fb` | 背景光晕·紫晶 | 承载正文 |
| `--gem-halo-topaz` | `#ffe6c4` | 背景光晕·蜜金 | 承载正文 |
| `--gem-ink-deep` | `#16233a` | 浅底正文 | — |
| `--gem-muted-deep` | `#5a6b84` | 浅底次要文字、注释 | 承载正文 |
| `--gem-aqua-deep` | `#0c6d84` | 浅底主强调：可交互、当前选中 | 大面积背景承载文字 |
| `--gem-topaz-deep` | `#96601a` | 浅底写入、提示 | 同上 |
| `--gem-emerald-deep` | `#2a7048` | 浅底已确认、正常、通过 | 同上 |
| `--gem-ruby-deep` | `#a8324f` | 浅底错误、阻断、越界 | 同上 |

规则：

- 高饱和色只出现在**边框、图标、轴、光棱、状态点**上，正文永远用 `--gem-ink` / `--gem-muted`（深底）或 `--gem-ink-deep` / `--gem-muted-deep`（浅底）。
- 强调色一次只表达一件事（可交互 或 当前选中），不混用。
- 浅底强调色与深底强调色**色相相同、明度不同**，语义一一对应（aqua↔aqua-deep、topaz↔topaz-deep、emerald↔emerald-deep、ruby↔ruby-deep、violet↔`--gem-halo-violet`）。
- 三维场景的实体颜色来自**类型**，来自一组固定色（见 §4.3），且必须与实体类型的语义一致，不得按选中状态改色。

## 4. 三维材质规则

### 4.1 几何

- **实体 = 晶体**：多面体（切角立方体或八面体），不用球。球没有棱线，就不是宝石。
- **容器（楼/层/房间）= 线框**：只画棱线，不画实心体；楼层可有一块半透明底板。
- **关系 = 光线**：细管、半透明、未选中时更淡。信任边界一类用分段几何表示虚线，不得用贴图。

### 4.2 晶体主体与棱线

- 实体主体：半透明（不透明度 0.45–0.7），低粗糙度、低金属度。光的分阶与墨线见第 13 章。
- 实体棱线：**始终可见**，亮度高于晶体主体；选中时棱线提到最亮并加内发光，主体不透明度略微提高。
- 棱线是宝石与普通方块的区别。没有棱线的半透明方块不是宝石。

### 4.3 类型色板

三维实体按类型取色，未登记的类型使用统一的中性灰（不与任何已登记类型同色）：

| 类型 | 颜色 | 类型 | 颜色 |
|---|---|---|---|
| system | `#6fb3ff` | actor | `#ff9a8b` |
| service | `#ffc46b` | gateway | `#ffd166` |
| module | `#9ad36f` | plugin | `#c8f06a` |
| process | `#d59bff` | security | `#ff7b9c` |
| data | `#7fe3d4` | operations | `#7fd1ff` |
| database | `#7fb0ff` | runtime | `#c9d1d9` |
| storage | `#c0a6ff` | external | `#8a94a6` |

### 4.4 坐标轴

- 三根轴各占一种宝石色：X=`--gem-aqua`、Y=`--gem-violet`、Z=`--gem-topaz`。
- 每根轴画成一根光柱，刻度处有一道短横，刻度值是标签。
- **轴值是类别不是度量**：不得把顺序型数值伪装成可比较度量；一根轴只有一个取值时，必须显式报告「该轴不提供独立信息」。

### 4.5 灯光

- 一盏环境光 + 一盏主光 + 一盏冷色补光，比例约 0.66 / 0.80 / 0.30。
- 公开场景的背景用 `--gem-void`，让棱线自己发亮。禁止过曝光晕、禁止体积雾、禁止地面反射。

### 4.6 三维禁止项（公开场景）

- ❌ 持续自转、呼吸缩放、粒子、拖尾。
- ❌ 彩虹渐变贴图、噪声贴图、扫描线。
- ❌ 用三维装饰承载模型里没有的事实（假楼层、假房间、假设备）。

后台工具面的律动是第 12.4 条的**唯一**例外：它只改姿态与亮度，不改几何、布局与配色。

## 5. 界面规则

| 元素 | 规则 |
|---|---|
| 页面底 | `--gem-bg` 纯色；三维画布内部用 `--gem-void` |
| 面板 / 顶栏 | `--gem-panel` 底 + 1px `--gem-rim` 下棱线；不使用多层投影 |
| 卡片 | `--gem-facet` 底 + 1px `--gem-rim` 边 + 极轻内高光（1px，不做投影堆叠） |
| 按钮 | 默认透明底 + 1px `--gem-rim` 边；悬停时边变 `--gem-aqua`；按下时底变 `--gem-facet` |
| 当前选中 | `--gem-aqua` 的 1px 边 + `--gem-aqua` 文字，不换背景大面积上色 |
| 焦点 | 2px `--gem-aqua` 外轮廓（`outline`），不得移除 |
| 分隔条 | 常态不可见，悬停/拖拽时显出 2px `--gem-aqua` |
| 状态徽记 | 圆点 + 文字；已确认 `--gem-emerald`，提示 `--gem-topaz`，错误 `--gem-ruby` |

- **磨砂只允许出现在外壳层**（顶栏、侧栏、检查器），且必须有实体底色衬托；正文区、数据表、代码块一律不透明。
- 圆角统一 6px（小控件 4px），大块面板 8px。
- 后台不适用本节的两条底色规则：它有自己的玻璃外壳（12.2）。

## 6. 动效

| 场景 | 规则 |
|---|---|
| 悬停 / 聚焦反馈 | 80–120ms，只改颜色与棱线亮度，不做位移与缩放 |
| 选中 | 即时切换，不做渐变动画 |
| 公开三维场景 | 静止即静止；只有相机与读者操作引起的变化 |
| 后台工具面 | 缓慢自转与呼吸辉光（第 12.4 条）；幅度小、周期长、可关闭 |
| 面板展开 | ≤160ms，且不改变主栏的最小宽度下限 |

禁止（公开场景与界面）：循环动画、进场逐项淡入、入场自动旋转。

## 7. 可访问性

- 正文对比度 ≥ 4.5:1，次要文字 ≥ 3:1。
- 颜色不单独承载事实：状态永远是「颜色 + 形状/文字」。
- 所有可拖拽分隔条可聚焦、可键盘调节（当前宽度以 `aria` 数值属性或可见文字给出）。
- 三维拾取失败时必须显式说明，不得用二维图伪装三维。
- 持续律动必须尊重 `prefers-reduced-motion`：系统要求减少动效时，后台工具面**静止**。

## 8. 反面清单

- ❌ 磨砂压在数据表或代码块上。
- ❌ 霓虹粉紫渐变铺底、彩虹色文字。
- ❌ 公开三维场景的物件持续自转或呼吸。
- ❌ 用颜色承载事实、却没有形状或文字冗余。
- ❌ 圆角 + 多层投影堆叠出体积感。
- ❌ 为了「像宝石」而牺牲正文可读性。
- ❌ 三维场景自创一套与 Unity 不同的手势（见 §9）。
- ❌ 用第二套底色表达「浅色模式」（浅底是第 3.2 节登记的色板，不是另一张皮）。
- ❌ 首屏把协议字段、枚举与原始值堆成一排标签（第 12.6 条）。

## 9. 三维操作与 Unity 一致

三维不只是「看起来像三维」，它也是一套**操作模型**。读者按 Unity 的肌肉记忆操作 GemArc 的三维场景时，必须得到同样的结果。因此凡是对三维模型的操作语义——相机、选择、框选、聚焦——一律以 Unity 2022.3 的场景视图为准；本站不发明第二套手势。

### 9.1 映射表（唯一口径）

| 操作 | 快捷键 | 作用 | Unity 对应 |
|---|---|---|---|
| 环绕 | Alt + 左键拖动 | 绕枢轴旋转视角 | Alt + Left Mouse Drag |
| 平移 | 中键拖动 | 枢轴随视线平行移动 | Middle Mouse Drag |
| 飞行 | 右键拖动 | 相机自由飞行，用 W/A/S/D 与 Q/E 移动 | Right Mouse Drag |
| 推拉 | 滚轮 | 镜头沿视线推近或拉远 | Mouse Wheel |
| 选择 | 左键点击 | 选中指针下的实体或关系 | Left Mouse Click |
| 加选 | Ctrl + 左键点击 | 把目标加入选择，或从选择中移除 | Ctrl + Left Mouse Click |
| 框选 | 左键在空白处拖动 | 选中矩形内的全部目标 | Left Mouse Drag on empty space |
| 清空 | 左键点击空白处或 Esc | 清空当前选择 | Left Mouse Click on empty space / Esc |
| 聚焦 | F | 把视角对准当前选择 | F (Frame Selected) |

这张表在代码里**只有一份**：`scaffold/runtime/space/unity-controls.js` 的 `UNITY_CONTROL_MAP`。页面上的操作提示、本节这张表和代码由同一条测试绑定；改一处而漏掉另一处会被门禁拦下。

### 9.2 语义细则

- **左键只做选择**。左键拖动不再旋转视角：拖到空白处是框选，拖在目标上什么也不发生。这既与 Unity 一致，也根除了「想点选却把场景转跑了」这一类误操作。
- **修饰键优先于模式**：Alt 让左键变成环绕，Ctrl 让左键变成加选；两者不同时生效。
- **按下与拖动由位移区分**：位移小于 5 像素算点击，大于等于 5 像素算拖动。判定只看位移，不看按钮——这是「点得中」与「转得动」能同时成立的前提。
- **选择状态只有一份**：三维场景不自己保存选择，选择住在跨视图状态里，因此二维图与三维场景永远一致。
- **框选按位置判定**：实体落在矩形内即被选中；关系要两端都在矩形内才算被选中——半条关系不是关系。
- **F 聚焦选中**：有选中时对准选中，没有选中时对准整个场景。
- **点击空白处与 Esc 都清空选择**。

### 9.3 与宝石主题的关系

- 宝石色板不变：颜色仍然只编码事实（类型、轴、状态），不编码操作。
- Unity 式红/绿/蓝只允许出现在**操作提示元素**类元素上（例如框选矩形的边），不得改写实体颜色，也不得取代「选中 = 亮棱线」这条规则。
- 三维操作提示以一行小字放在画布下方，字号与次要文字一致，不喧宾夺主。

## 11. 验收口径

一条产出算「符合本方针」，当且仅当：

1. **公开**三维场景里**没有**持续动画，实体**有**可见棱线，关系是细管而不是实心杆；
2. 场景背景是 `--gem-void`，界面底色是 `--gem-bg`，两者肉眼可分；
3. 页面上每一种强调色都能对应到「可交互」或「当前选中」之一；
4. 正文没有任何一处压在半透明层上；
5. 同一个模型渲染两次，场景**逐像素一致**（确定性是宝石主题的一部分：同一颗宝石，切面必须一样）；
6. §9.1 的九行手势逐条可复现：左键点击选中、点击空白清空、Ctrl 加选、拖动框选、Alt 环绕、中键平移、右键飞行、滚轮推拉、F 聚焦、Esc 清空；
7. 两个三维场景（语义轴、楼/层/房间）对同一套手势的反应**完全一致**；
8. **后台工具面**的律动只改姿态与亮度：同一份工具表，几何、位置与配色逐个不变（律动的帧本身不参与第 5 条的逐像素比对）。
9. **后台三个界面与工具描述都是三语**：`zh-CN` / `ja-JP` / `en-US` 三张表键集合相同；切换语言只改文字，不改事实、ID、协议字段与证据状态；取不到键时显示键本身并记一条缺口。

## 12. 后台界面（控制台、账号页、运营区）

后台 = 三个界面：MCP 控制台（`/`）、账号页（`/account`）、运营区（`/account/admin`）。它们与公开站点是**同一个产品**，画风必须一致 —— 只是从暗场的展柜换到亮场的玻璃柜。

### 12.1 色板只有一个来源

- 后台**共用第 3 节登记的全部 `--gem-*` 令牌**（3.1 深底档 + 3.2 浅底档），不得另起一套近似色（例如「另一组 `--bg/--panel/--accent`」）。同名不同义、同义不同名都不允许。
- 后台若需要一个色板之外的语义色，先在第 3 节登记它，再在代码里使用它。
- 浅底上的强调色用第 3.2 节的深档（`-deep`），不另造颜色。

### 12.2 界面语言：通透水晶

- 后台是**浅色单主题**：账号页与运营区不随系统的深色偏好切换 —— 第二套底色就是第二套近似色（`color-scheme` 固定为 light）。
- 页面底是 `--gem-air`；玻璃层是 `--gem-sheen` 叠在空气层上，带背景模糊与极轻投影（**本条是第 3、5 条的唯一例外**：玻璃必须有一层极轻投影才浮得起来，投影只有一层、只有玻璃层有）。
- **背景光晕**：页面底上允许三片大尺寸径向渐变（`--gem-halo-aqua`、`--gem-halo-violet`、`--gem-halo-topaz`），低饱和、无边框、不承载事实。光晕是静态的，不做循环漂移。
- 三维画布仍然是深色（`--gem-void`）：玻璃柜里嵌一只暗色展柜，晶体才亮得起来。
- 正文用 `--gem-ink-deep` / `--gem-muted-deep`；强调用 `-deep` 档。
- 卡片 = 玻璃面 + 1px 亮边 + 极轻内高光；数据表、代码块、JSON 结果**一律不透明**（`--gem-sheen` 实底）。
- 圆角统一 10px（玻璃质感需要更圆的角），小控件 6px。

### 12.3 「事实」在后台指运行态事实

第 2.1 条的「事实」在后台不是模型字段，而是**服务端的运行态事实**：注册的工具、资源、提示词、账号、审计条目、开关取值、部署状态。

因此：

- 后台的界面元素只要对应上面这些事实之一，就是合规的；反之（画一个不存在的楼层、不存在的设备、不存在的工具）一律禁止。
- **品牌标记**（GemArc 的晶体标志）承载品牌而不是事实：它只允许出现在标题区与站点标识位置，不得动画、不得承载交互语义，也不得当成数据。
- 控制台的三维场景**必须**由运行态事实生成：第 13 条的材质规则对它同样成立，它画的每一个晶体都对应一个真实注册的工具。

### 12.4 后台三维场景（控制台）

- 控制台提供一块**可交互**的三维晶体场景，承载服务器的**工具面**：每个注册的工具一颗晶体，按只读/写入分成两种色。
- 两种色取自色板：只读晶体 = `--gem-aqua`，写入晶体 = `--gem-topaz`。颜色不单独承载事实，场景旁必须有同样的图例文字。
- 布局是**确定的**：第 n 个工具落在黄金角螺旋的第 n 个位置，同一份工具表渲染两次，晶体的位置逐个相同（承接第 11.5 条）。
- 没有注册工具就没有晶体：控制台的三维场景只画服务端真实注册的工具，不得画占位晶体充数。
- 材质与手势都来自**共享模块**：控制台场景导入 `toon-material.js` 与 `unity-controls.js`，不另写一份（承接第 13.4 条）。
- 拾取一颗晶体 = 选中那个工具（与二维工具列表同一份选择状态，一处变另一处跟着变）。
- 手势沿用第 9.1 节的九行映射，与两个公开场景共用同一份实现。
- 三维不可用时（没有 WebGL、脚本没有取到三维库）面板**如实说明「未加载」**，控制台的其余功能照旧可用；不得用一张图片假装三维。
- **律动**：晶体缓慢自转，亮度随时间呼吸（周期约 6 秒，自转一周约 60 秒）。律动只改姿态与亮度，**不改几何、位置与配色**（第 11.8 条）。
- 律动必须可关：系统开启「减少动效」（`prefers-reduced-motion: reduce`）时，场景静止，只保留读者操作引起的变化。

### 12.5 可访问性不变

- 正文对比度 ≥ 4.5:1，次要文字 ≥ 3:1。
- 颜色不单独承载事实：状态永远是「颜色 + 形状/文字」。
- 后台的表格与表单在窄视口下允许换行与横向滚动，但**不得**为了「像宝石」而删掉字段、截断可读性或把关键操作藏进悬停。

### 12.6 信息密度

- **首屏状态行不超过 5 个要点**，且每个要点是一个短语，不是一个键值对。协议路径、传输方式、工具集这类技术值**折叠到详情**，不占首屏。
- 状态用**当前语言**的短语（中文：「工具 9」「只读」「站点未构建」；日文与英文同理），原始英文值放进详情或页脚。
- 一次只回答一个问题：面板顶部回答「服务器是什么状态」，工具区回答「我能调什么」，舞台回答「这一个工具怎么用」。
- 错误提示一句话说完，不重复、不追加解释性长句。

### 12.7 语言切换

- 后台三个界面（控制台、账号页、运营区）与 **MCP 工具描述**都提供三语：`zh-CN` / `ja-JP` / `en-US`。文字的**唯一来源**是 `src/gemarc_mcp/i18n/<locale>.json`，三张表的键集合必须相同。
- **选择顺序**：本机记住的选择 → 浏览器语言（`Accept-Language` / `navigator.language`）→ `zh-CN`。
- 切换只改**显示文字**：模型 ID、工具名、参数名、协议字段、证据状态一律不变（第 2.1 条、第 12.3 条）。
- 切换器是**一行三个选项**，放在页头；每个选项用**自己的语言**写自己（「中文」「日本語」「English」），不用语言代码当标签。
- 切换不改变布局：首屏仍不超过 5 个要点（第 12.6 条），三语的要点条数相同。
- 控制台有脚本，语言选择记在**本机**（`localStorage`），不写进 URL；账号页与运营区**没有脚本**，语言切换用链接（`?lang=`）并记在 Cookie 里。
- **缺键不得静默混语**：取不到键时显示键本身，并记一条缺口；三张表键集合不一致就是缺陷，不是可接受状态。

## 13. 三渲二（cel shading）材质规则

三维画风是**美漫式的三渲二**：光被分成明确的阶，阶与阶之间是硬边，而不是连续的渐变阴影。

### 13.1 分阶

- 光在晶体的**切面**上被量化为 **3 阶**：暗、中、亮。阶与阶之间是硬边，不得出现连续渐变。
- 实现用 `MeshToonMaterial` 加一张 **3 阶渐变贴图**（`DataTexture`，3 个像素宽）。贴图是**常量**：不随实体、不随选中状态变化，因此同一模型两次渲染逐像素一致（承接第 11.5 条）。
- 晶体的主体仍然半透明（第 4.2 条的 0.45–0.7 区间不变），棱线仍然始终可见。

### 13.2 墨线

- **墨线就是晶体自己的棱线**：既有的棱边几何与亮棱线就是勾边，线宽随强调程度变化（第 4.2 条）。
- 不得再叠加屏幕空间描边、描边网格或第二层外扩网格：宝石的边来自它被切割过，不是来自后期描边。

### 13.3 禁止项（与第 4.6 节并列）

- ❌ 连续渐变阴影（未量化的 PBR 高光）。
- ❌ 体积雾、地面反射、过曝。
- ❌ 半调网点、扫描线、材质噪声贴图、彩虹渐变。
- ❌ 公开场景里的自转、呼吸缩放、粒子、拖尾。

允许（仅后台工具面）：材质自发光强度随时间缓慢变化，形成呼吸辉光。它**不得**引入新的贴图、新的着色器或第四个明度阶 —— 呼吸辉光只是自发光强度的变化。

### 13.4 只有一份实现

- 三渲二的材质实现住在**一个模块**里，两个公开场景与控制台的后台场景都用它。三处各写一份必然漂移，绑定测试会拦住这种漂移。
- 材质模块不依赖任何三维库的具体版本细节，只使用「材质类 + 渐变贴图」这两个标准接口。
