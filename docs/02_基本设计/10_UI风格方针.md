## 1. 立意：宝石是被切割过的结构

GemArc 的名字里有一个 Gem。宝石之所以是宝石，不是因为它有颜色，而是因为它**被切割过**：它同时具备秩序（对称的面）与光（棱线上的高光）。所以本方针不是「把界面做成宝石的样子」，而是：

- **界面像切面**：信息被切成边界清楚的面，面与面之间是棱线，不是阴影堆叠。
- **三维像晶体**：实体是被打磨过的多面体，棱线勾出它的形；关系是穿过它们的光线。
- **光要克制**：宝石的美来自一小片高光。大面积高光会让水晶变成塑料。
- **同一张纸**：公开站点与后台都是一张纸（第 3 节）。

> v3.4 变更：画风由「暗场里的发光宝石」改为**和紙墨描**（第 16 节）。**几何与语义不变** —— 仍是被切割过的结构，仍由颜色编码事实；变的是**用笔**：不再发光、不再半透明，边是墨线而不是亮棱，底是纸而不是暗场。

一句话方针：**切面、墨线、少量高光不变；颜色只编码事实，不负责好看。**

## 2. 六条信条

1. **语义优先，装饰为零**：每一个可见元素都必须对应模型里的一个事实。无法对应事实的装饰一律不做。
2. **颜色是编码，不是修饰**：同一颜色在站点与三维场景里必须指同一件事。颜色永远配形状或文字，不单独承载事实。
3. **切面而不是阴影**：层级用 1px 棱线与底色差表达，不用多层投影堆出体积感。
4. **静者静，动者有度**：公开站点静止即静止（没有自转、没有呼吸、没有循环动画）；后台工具面允许缓慢律动，但律动**不得承载任何事实** —— 晶体的位置、颜色、数量仍然由事实决定（第 12.4 条）。
5. **可读性高于气质**：正文对比度不低于 4.5:1。任何「晶莹」处理不得压住文字与数据。
6. **简明高于完整**：界面用最少的字说清一件事。技术值、原始枚举、英文协议字段折叠到详情里，首屏不堆叠（第 12.6 条）。

## 3. 色板（唯一色源）

站点、三维场景与后台共用同一组令牌。令牌名写在 CSS 变量里，三维场景在 JavaScript 里使用同名常量。

**令牌名只允许小写字母、数字与连字符；值一律写成 6 位十六进制。**

> v3.4 变更：整块色板改为**和紙（生成り）侘寂** —— 纸、墨与传统颜料，依据与硬约束见第 16 节。
> 原「深底 3.1 + 浅底 3.2」两套并存的写法**取消**：站点与后台现在都是纸面，只剩**一张**色板；
> 强调色也不再有「亮档 / `-deep` 暗档」之分，一色到底。

### 3.1 纸与墨

| 令牌 | 值 | 用途 | 禁止 |
|---|---|---|---|
| `--gem-void` | `#d6c9ae` | 底下一层纸：页面外缘、纸边、卡片硬偏移影 | — |
| `--gem-bg` | `#ebe1ce` | 页面底（生成り和紙）；三维画布底 | — |
| `--gem-panel` | `#f4eddf` | 面板、顶栏、检查器底（晒白纸） | — |
| `--gem-facet` | `#e6dac6` | 卡片底、分隔面（糙米纸） | 承载正文 |
| `--gem-rim` | `#a89a7c` | 棱线、边框、分隔条（土与竹的边） | — |
| `--gem-ink` | `#2e2a24` | 正文、结构墨线（墨） | — |
| `--gem-muted` | `#6e6354` | 次要文字、注释、淡墨线（茶墨） | 承载正文 |

### 3.2 顔料（五种，各只编码一件事）

| 令牌 | 值 | 颜色 | 用途 | 禁止 |
|---|---|---|---|---|
| `--gem-ai` | `#3d5a72` | 藍 | 主强调：可交互、当前选中、坐标轴 X | 大面积背景承载文字 |
| `--gem-fuji` | `#5f5573` | 藤 | 次强调：坐标轴 Y、辅助序列 | 同上 |
| `--gem-kaki` | `#96501f` | 柿 | 坐标轴 Z、提示 | 同上 |
| `--gem-koke` | `#56663a` | 苔 | 已确认、正常、通过 | 同上 |
| `--gem-sabi` | `#8a3a2c` | 錆 | 错误、阻断、越界 | 同上 |

规则：

- **颜色仍然只编码事实**，语义映射与旧版一一对应（可交互 / 次强调 / 提示 / 通过 / 错误），换的只是颜色。
- 五种颜料全部**低彩度**（CIELAB 彩度 C\* ≤ 50，实测最大 47.6 = 柿）：霓虹色不进色板（第 16.2 条）。
- 强调色一次只表达一件事（可交互 **或** 当前选中），不混用。
- 三维实体颜色来自**类型**（第 4.3 节），且必须与实体类型的语义一致，不得按选中状态改色。

## 4. 三维材质规则

### 4.1 几何

- **实体 = 晶体**：多面体（切角立方体或八面体），不用球。球没有棱线，就不是宝石。
- **容器（楼/层/房间）= 线框**：只画棱线，不画实心体；楼层可有一块半透明底板。
- **关系 = 光线**：细管、半透明、未选中时更淡。信任边界一类用分段几何表示虚线，不得用贴图。

### 4.2 晶体主体与墨线

- 实体主体：**不透明、平涂**、低粗糙度、低金属度。光的分阶见第 13 章。**不做半透明** —— 半透明是水晶玻璃的画法；和紙墨描是实笔画法，纸不透光。
- 实体轮廓：**始终可见的墨线**，颜色固定为 `--gem-ink`（**不是**主体色的提亮 —— 提亮的边是宝石的画法，墨描的边永远是墨色）。选中时墨线加粗一档，主体颜色不变。
- 墨线是刻面与普通方块的区别。没有墨线的实心方块不是被切割过的结构。
- 容器（楼/层/房间）仍是**线框**，关系仍是**细管**；线框与细管用 `--gem-rim` 一类的土色，不发光。

### 4.3 类型色板

三维实体按类型取色，未登记的类型使用统一的中性灰（不与任何已登记类型同色）。全部取自第 3.2 节五种颜料的浅/深档，CIELAB 彩度 C\* 一律 ≤ 50（实测最大 47.6）：

| 类型 | 颜色 | 类型 | 颜色 |
|---|---|---|---|
| system | `#3d5a72` | actor | `#b4654a` |
| service | `#96501f` | gateway | `#a9762f` |
| module | `#56663a` | plugin | `#6e7b45` |
| process | `#5f5573` | security | `#8a3a2c` |
| data | `#5a7566` | operations | `#7e8b93` |
| database | `#4c6e7a` | runtime | `#8c8271` |
| storage | `#6b5f7e` | external | `#8f8577` |

未登记类型：`#9c927f`（土・灰）。

### 4.4 坐标轴

- 三根轴各占一种颜料：X=`--gem-ai`（藍）、Y=`--gem-fuji`（藤）、Z=`--gem-kaki`（柿）。
- 每根轴画成一根光柱，刻度处有一道短横，刻度值是标签。
- **轴值是类别不是度量**：不得把顺序型数值伪装成可比较度量；一根轴只有一个取值时，必须显式报告「该轴不提供独立信息」。

### 4.5 灯光

- 一盏环境光 + 一盏主光 + 一盏**暖色**补光（纸面反弹光），比例约 0.75 / 0.55 / 0.25。**没有冷蓝补光**。
- 公开场景的背景用 `--gem-bg`（纸）。禁止过曝光晕、禁止体积雾、禁止地面反射、禁止发光材质（`emissive` 恒为 0，只有后台工具面的呼吸律动例外，见第 12.4 条）。

### 4.6 三维禁止项（公开场景）

- ❌ 持续自转、呼吸缩放、粒子、拖尾。
- ❌ 彩虹渐变贴图、噪声贴图、扫描线。
- ❌ 用三维装饰承载模型里没有的事实（假楼层、假房间、假设备）。
- ❌ **发光**：自发光材质、霓虹边线、纯黑纯白的描边。
- ❌ 半透明主体（纸面是实心的）。

后台工具面的律动是第 12.4 条的**唯一**例外：它只改姿态与亮度，不改几何、布局与配色。

## 5. 界面规则

| 元素 | 规则 |
|---|---|
| 页面底 | `--gem-bg` 纯色 + 和紙纤维底纹（第 14.5 条）；三维画布内部同用 `--gem-bg` |
| 面板 / 顶栏 | `--gem-panel` 底 + 1px `--gem-rim` 下棱线；不使用多层投影 |
| 卡片 | `--gem-facet` 底 + 1px `--gem-muted` 边 + 极轻内高光（1px 暖白，不做投影堆叠） |
| 按钮 | 默认透明底 + 1px `--gem-muted` 边；悬停时边变 `--gem-ai`；按下时底变 `--gem-facet` |
| 当前选中 | `--gem-ai` 的 1px 边 + `--gem-ai` 文字，不换背景大面积上色 |
| 焦点 | 2px `--gem-ai` 外轮廓（`outline`），不得移除 |
| 分隔条 | 常态不可见，悬停/拖拽时显出 2px `--gem-ai` |
| 状态徽记 | 圆点 + 文字；已确认 `--gem-koke`，提示 `--gem-kaki`，错误 `--gem-sabi` |

- **纸面不磨砂**：外壳层（顶栏、侧栏、检查器）也是实底纸，不做背景模糊、不做玻璃。
- 圆角统一 6px（小控件 4px），大块面板 8px。
- 后台不适用本节的底色规则：它有自己的纸面规则（12.2）。

## 6. 动效

| 场景 | 规则 |
|---|---|
| 悬停 / 聚焦反馈 | 80–120ms，只改颜色与棱线亮度，不做位移与缩放 |
| 选中 | 即时切换，不做渐变动画 |
| 公开三维场景 | 静止即静止；只有相机与读者操作引起的变化 |
| 后台工具面 | 缓慢自转与呼吸辉光（第 12.4 条）；幅度小、周期长、可关闭 |
| 面板展开 | ≤160ms，且不改变主栏的最小宽度下限 |

禁止（公开场景与界面）：循环动画、进场逐项淡入、入场自动旋转。

## 7. 可访问性

- 正文对比度 ≥ 4.5:1，次要文字 ≥ 3:1。
- 颜色不单独承载事实：状态永远是「颜色 + 形状/文字」。
- 所有可拖拽分隔条可聚焦、可键盘调节（当前宽度以 `aria` 数值属性或可见文字给出）。
- 三维拾取失败时必须显式说明，不得用二维图伪装三维。
- 持续律动必须尊重 `prefers-reduced-motion`：系统要求减少动效时，后台工具面**静止**。

## 8. 反面清单

- ❌ 磨砂压在数据表或代码块上；**任何**玻璃与背景光晕（侘寂是纸，不是玻璃）。
- ❌ 霓虹粉紫渐变铺底、彩虹色文字、纯黑纯白（**色板上没有这两个颜色**）。
- ❌ 公开三维场景的物件持续自转或呼吸。
- ❌ 用颜色承载事实、却没有形状或文字冗余。
- ❌ 圆角 + 多层投影堆叠出体积感。
- ❌ 为了「像宝石」而牺牲正文可读性。
- ❌ 三维场景自创一套与 Unity 不同的手势（见 §9）。
- ❌ 用第二套底色表达「浅色模式」（**只有一张色板**，见第 3 节）。
- ❌ 首屏把协议字段、枚举与原始值堆成一排标签（第 12.6 条）。
- ❌ 产出没有经过一次**整体** UI/UX 优化就交付（第 15 条）。
- ❌ 用模糊投影、渐变填充或噪声贴图做「漫画感」（第 14 条）。
- ❌ 让三维实体发光、半透明或用霓虹描边（第 4.6 条）。

## 9. 三维操作与 Unity 一致

三维不只是「看起来像三维」，它也是一套**操作模型**。读者按 Unity 的肌肉记忆操作 GemArc 的三维场景时，必须得到同样的结果。因此凡是对三维模型的操作语义——相机、选择、框选、聚焦——一律以 Unity 2022.3 的场景视图为准；本站不发明第二套手势。

### 9.1 映射表（唯一口径）

| 操作 | 快捷键 | 作用 | Unity 对应 |
|---|---|---|---|
| 环绕 | Alt + 左键拖动 | 绕枢轴旋转视角 | Alt + Left Mouse Drag |
| 平移 | 中键拖动 | 枢轴随视线平行移动 | Middle Mouse Drag |
| 飞行 | 右键拖动 | 相机自由飞行，用 W/A/S/D 与 Q/E 移动 | Right Mouse Drag |
| 推拉 | 滚轮 | 镜头沿视线推近或拉远 | Mouse Wheel |
| 选择 | 左键点击 | 选中指针下的实体或关系 | Left Mouse Click |
| 加选 | Ctrl + 左键点击 | 把目标加入选择，或从选择中移除 | Ctrl + Left Mouse Click |
| 框选 | 左键在空白处拖动 | 选中矩形内的全部目标 | Left Mouse Drag on empty space |
| 清空 | 左键点击空白处或 Esc | 清空当前选择 | Left Mouse Click on empty space / Esc |
| 聚焦 | F | 把视角对准当前选择 | F (Frame Selected) |

这张表在代码里**只有一份**：`scaffold/runtime/space/unity-controls.js` 的 `UNITY_CONTROL_MAP`。页面上的操作提示、本节这张表和代码由同一条测试绑定；改一处而漏掉另一处会被门禁拦下。

### 9.2 语义细则

- **左键只做选择**。左键拖动不再旋转视角：拖到空白处是框选，拖在目标上什么也不发生。这既与 Unity 一致，也根除了「想点选却把场景转跑了」这一类误操作。
- **修饰键优先于模式**：Alt 让左键变成环绕，Ctrl 让左键变成加选；两者不同时生效。
- **按下与拖动由位移区分**：位移小于 5 像素算点击，大于等于 5 像素算拖动。判定只看位移，不看按钮——这是「点得中」与「转得动」能同时成立的前提。
- **选择状态只有一份**：三维场景不自己保存选择，选择住在跨视图状态里，因此二维图与三维场景永远一致。
- **框选按位置判定**：实体落在矩形内即被选中；关系要两端都在矩形内才算被选中——半条关系不是关系。
- **F 聚焦选中**：有选中时对准选中，没有选中时对准整个场景。
- **点击空白处与 Esc 都清空选择**。

### 9.3 与宝石主题的关系

- 宝石色板不变：颜色仍然只编码事实（类型、轴、状态），不编码操作。
- Unity 式红/绿/蓝只允许出现在**操作提示元素**类元素上（例如框选矩形的边），不得改写实体颜色，也不得取代「选中 = 墨线加粗」这条规则。
- 三维操作提示以一行小字放在画布下方，字号与次要文字一致，不喧宾夺主。

## 11. 验收口径

一条产出算「符合本方针」，当且仅当：

1. **公开**三维场景里**没有**持续动画，实体**有**可见墨线，关系是细管而不是实心杆；
2. 场景背景与界面底色都是纸（`--gem-bg`），实体是**不透明**平涂 + 墨线，**没有**发光与半透明；
3. 页面上每一种强调色都能对应到「可交互」或「当前选中」之一；
4. 正文没有任何一处压在半透明层上；
5. 同一个模型渲染两次，场景**逐像素一致**（确定性是宝石主题的一部分：同一颗宝石，切面必须一样）；
6. §9.1 的九行手势逐条可复现：左键点击选中、点击空白清空、Ctrl 加选、拖动框选、Alt 环绕、中键平移、右键飞行、滚轮推拉、F 聚焦、Esc 清空；
7. 两个三维场景（语义轴、楼/层/房间）对同一套手势的反应**完全一致**；
8. **后台工具面**的律动只改姿态与亮度：同一份工具表，几何、位置与配色逐个不变（律动的帧本身不参与第 5 条的逐像素比对）。
9. **后台三个界面与工具描述都是三语**：`zh-CN` / `ja-JP` / `en-US` 三张表键集合相同；切换语言只改文字，不改事实、ID、协议字段与证据状态；取不到键时显示键本身并记一条缺口。
10. **平面层带着第 14 条的和紙墨描**：结构元素有明确墨线，面是平涂，需要浮起感的地方是硬边偏移影而不是模糊投影，纸底有纤维质地，分格之间有留白；**产出经过了一次整体 UI/UX 优化**，且最终说明里写了这一轮做了什么（第 15 条）。
11. **第 16 条的五条硬约束全部成立**：色板里没有纯黑纯白、彩度在上限内、纸的三个面明度相邻、强调色面积不超过 5%、正文与控件的对比度达下限。

## 12. 后台界面（控制台、账号页、运营区）

后台 = 三个界面：MCP 控制台（`/`）、账号页（`/account`）、运营区（`/account/admin`）。它们与公开站点是**同一个产品**，画风必须一致 —— 站点与后台现在都是**同一张纸**。

### 12.1 色板只有一个来源

- 后台**共用第 3 节登记的全部 `--gem-*` 令牌**（纸与墨 3.1 + 顔料 3.2），不得另起一套近似色（例如「另一组 `--bg/--panel/--accent`」）。同名不同义、同义不同名都不允许。
- 后台若需要一个色板之外的语义色，先在第 3 节登记它，再在代码里使用它。

### 12.2 界面语言：和紙

- 后台是**浅色单主题**：账号页与运营区不随系统的深色偏好切换（`color-scheme` 固定为 light）。
- 页面底是 `--gem-bg`（生成り和紙）+ 纸纤维底纹；**没有玻璃层、没有背景光晕、没有背景模糊**（第 8 节：侘寂是纸，不是玻璃）。
- 三维画布与公开场景同一张纸（`--gem-bg`）。
- 正文用 `--gem-ink` / `--gem-muted`；强调用五种颜料。
- 卡片 = `--gem-panel` 或 `--gem-facet` 实底 + 1px `--gem-muted` 边 + 极轻内高光；数据表、代码块、JSON 结果一律实底。
- 圆角统一 6px（小控件 4px），大块面板 8px —— 与公开站点一致，不再为玻璃质感放宽到 10px。

### 12.3 「事实」在后台指运行态事实

第 2.1 条的「事实」在后台不是模型字段，而是**服务端的运行态事实**：注册的工具、资源、提示词、账号、审计条目、开关取值、部署状态。

因此：

- 后台的界面元素只要对应上面这些事实之一，就是合规的；反之（画一个不存在的楼层、不存在的设备、不存在的工具）一律禁止。
- **品牌标记**（GemArc 的晶体标志）承载品牌而不是事实：它只允许出现在标题区与站点标识位置，不得动画、不得承载交互语义，也不得当成数据。
- 控制台的三维场景**必须**由运行态事实生成：第 13 条的材质规则对它同样成立，它画的每一个晶体都对应一个真实注册的工具。

### 12.4 后台三维场景（控制台）

- 控制台提供一块**可交互**的三维晶体场景，承载服务器的**工具面**：每个注册的工具一颗晶体，按只读/写入分成两种色。
- 两种色取自色板：只读晶体 = `--gem-ai`（藍），写入晶体 = `--gem-kaki`（柿）。颜色不单独承载事实，场景旁必须有同样的图例文字。
- 布局是**确定的**：第 n 个工具落在黄金角螺旋的第 n 个位置，同一份工具表渲染两次，晶体的位置逐个相同（承接第 11.5 条）。
- 没有注册工具就没有晶体：控制台的三维场景只画服务端真实注册的工具，不得画占位晶体充数。
- 材质与手势都来自**共享模块**：控制台场景导入 `toon-material.js` 与 `unity-controls.js`，不另写一份（承接第 13.4 条）。
- 拾取一颗晶体 = 选中那个工具（与二维工具列表同一份选择状态，一处变另一处跟着变）。
- 手势沿用第 9.1 节的九行映射，与两个公开场景共用同一份实现。
- 三维不可用时（没有 WebGL、脚本没有取到三维库）面板**如实说明「未加载」**，控制台的其余功能照旧可用；不得用一张图片假装三维。
- **律动**：晶体缓慢自转，亮度随时间呼吸（周期约 6 秒，自转一周约 60 秒）。律动只改姿态与亮度，**不改几何、位置与配色**（第 11.8 条）。
- 律动必须可关：系统开启「减少动效」（`prefers-reduced-motion: reduce`）时，场景静止，只保留读者操作引起的变化。

### 12.5 可访问性不变

- 正文对比度 ≥ 4.5:1，次要文字 ≥ 3:1。
- 颜色不单独承载事实：状态永远是「颜色 + 形状/文字」。
- 后台的表格与表单在窄视口下允许换行与横向滚动，但**不得**为了「像宝石」而删掉字段、截断可读性或把关键操作藏进悬停。

### 12.6 信息密度

- **首屏状态行不超过 5 个要点**，且每个要点是一个短语，不是一个键值对。协议路径、传输方式、工具集这类技术值**折叠到详情**，不占首屏。
- 状态用**当前语言**的短语（中文：「工具 9」「只读」「站点未构建」；日文与英文同理），原始英文值放进详情或页脚。
- 一次只回答一个问题：面板顶部回答「服务器是什么状态」，工具区回答「我能调什么」，舞台回答「这一个工具怎么用」。
- 错误提示一句话说完，不重复、不追加解释性长句。

### 12.7 语言切换

- 后台三个界面（控制台、账号页、运营区）与 **MCP 工具描述**都提供三语：`zh-CN` / `ja-JP` / `en-US`。文字的**唯一来源**是 `src/gemarc_mcp/i18n/<locale>.json`，三张表的键集合必须相同。
- **选择顺序**：本机记住的选择 → 浏览器语言（`Accept-Language` / `navigator.language`）→ `zh-CN`。
- 切换只改**显示文字**：模型 ID、工具名、参数名、协议字段、证据状态一律不变（第 2.1 条、第 12.3 条）。
- 切换器是**一行三个选项**，放在页头；每个选项用**自己的语言**写自己（「中文」「日本語」「English」），不用语言代码当标签。
- 切换不改变布局：首屏仍不超过 5 个要点（第 12.6 条），三语的要点条数相同。
- 控制台有脚本，语言选择记在**本机**（`localStorage`），不写进 URL；账号页与运营区**没有脚本**，语言切换用链接（`?lang=`）并记在 Cookie 里。
- **缺键不得静默混语**：取不到键时显示键本身，并记一条缺口；三张表键集合不一致就是缺陷，不是可接受状态。

### 12.8 会话与登出

- 控制台右上角有**登出**按钮，与**会话**同生死：没有会话（只有 MCP 令牌）时**不出现**。
- 登出是**带 CSRF 令牌的 POST 表单**，不是链接：没有脚本也能用，链接也永远不会触发它。
- 文案与账号页一致（登出 / サインアウト / Sign out）：同一件事只有一个名字。
- 它排在语言切换器与「设置」之后，并**用一条细线**与「设置」分开：结束会话是一个边界，不是又一个设置。

## 13. 三渲二（cel shading）材质规则

三维画风是**美漫式的三渲二**：光被分成明确的阶，阶与阶之间是硬边，而不是连续的渐变阴影。

### 13.1 分阶

- 光在晶体的**切面**上被量化为 **3 阶**：暗、中、亮。阶与阶之间是硬边，不得出现连续渐变。
- 实现用 `MeshToonMaterial` 加一张 **3 阶渐变贴图**（`DataTexture`，3 个像素宽）。贴图是**常量**：不随实体、不随选中状态变化，因此同一模型两次渲染逐像素一致（承接第 11.5 条）。
- 三阶的**暗档不得压到近黑**：纸面是实心平涂，暗档是「这一面背光」，不是「洞」。暗档亮度 ≥ 55%，亮档 100%。
- 晶体的主体**不透明**（第 4.2 条），棱线仍然是墨线（第 13.2 条）。

### 13.2 墨线

- **墨线就是晶体自己的棱线**：既有的棱边几何就是勾边，线宽随强调程度变化（第 4.2 条）。
- 墨线颜色**固定为 `--gem-ink`**（墨）：不是主体色的提亮 —— 提亮的边是宝石的画法。
- 不得再叠加屏幕空间描边、描边网格或第二层外扩网格：边来自它被切割过，不是来自后期描边。

### 13.3 禁止项（与第 4.6 节并列）

- ❌ 连续渐变阴影（未量化的 PBR 高光）。
- ❌ 体积雾、地面反射、过曝。
- ❌ 半调网点、扫描线、材质噪声贴图、彩虹渐变。
- ❌ 公开场景里的自转、呼吸缩放、粒子、拖尾。
- ❌ 半透明主体、自发光材质、霓虹描边。

允许（仅后台工具面）：材质自发光强度随时间缓慢变化，形成呼吸辉光。它**不得**引入新的贴图、新的着色器或第四个明度阶 —— 呼吸辉光只是自发光强度的变化。

### 13.4 只有一份实现

- 三渲二的材质实现住在**一个模块**里，两个公开场景与控制台的后台场景都用它。三处各写一份必然漂移，绑定测试会拦住这种漂移。
- 材质模块不依赖任何三维库的具体版本细节，只使用「材质类 + 渐变贴图」这两个标准接口。

## 14. 平面层的和紙墨描渲染

第 13 章的三渲二说的是三维。平面外壳此前只有「切面 + 亮棱」，没有**用笔**；本章补上：平面层用同一套墨描语言，纸面仍是底子。

一句话：**平涂 + 明确墨线 + 硬边偏移影 + 分格 + 和紙纤维**，颜色仍然只编码事实。

> v3.4 变更：原「美漫卡通渲染」的材料按侘寂改写 —— 墨线由**亮棱**改为**墨**（暗），硬边阴影仍是硬边但落在**纸上**，半调网点改为**和紙纤维**。

### 14.1 墨线

- 墨线是元素**自己的边**，不是后期叠加的轮廓（承接第 13.2 条：边来自它被切割过）。
- 平面层的墨线用 `--gem-muted`（淡墨 2px），主内容格用 `--gem-ink`（墨 3px）；**不是** `--gem-rim` —— 那是棱线与分隔条的弱一档。
- 控件与徽记（按钮、标签、芯片）用 1px 的边：它们不是结构件。可交互的控件用 `--gem-muted` 或 `--gem-ai`（第 16.2 条第 5 项：边界要看得见），纯徽记可以用弱一档的 `--gem-rim`。

### 14.2 平涂

- 面是纯色：不用渐变填充，不用背景图。

### 14.3 硬边阴影

- 需要浮起感的结构元素用**硬边**偏移影：偏移 3–4px、模糊半径 0、颜色 `--gem-void`（深一层的纸，像纸叠在纸上）。
- 只有一层，不堆叠（第 5 条）。

### 14.4 分格与标题框

- 主内容按「格」组织：每个维度视图是一格，格与格之间留白（侘寂的「間」）。
- 主内容格的墨线最重（`--gem-ink` 3px），其余格 2px `--gem-muted`。
- 面板标题是一枚**标题框**：实色底 `--gem-facet` + 2px 墨线 + 硬边阴影。

### 14.5 和紙纤维

- 页面底允许一层**极稀疏**的纤维底纹（CSS 细线，不是贴图、不是噪声）：这是和紙的质地。
- 纤维**不承载任何事实**，所以本条是第 2.1 条「装饰为零」的**唯一例外** —— 与第 12.3 条的品牌标记同理：它承载的是画风，不是信息。
- 纤维不得盖住正文与数据（第 7 条）：正文永远压在实底上。
- **禁止半调网点**（美漫印刷的机器纹）与噪点：纸的质地是纤维，不是网点。

### 14.6 克制

- 沿用第 1 条：光要克制。墨线变重不等于高光变多。
- 低彩度的颜料只出现在边框、图标、轴、状态点上（第 3.2 条）。

### 14.7 禁止项

- ❌ 模糊投影、多层投影堆叠、渐变填充、渐变文字、彩虹色、霓虹粉紫铺底。
- ❌ 半调网点、噪点、扫描线、材质噪声贴图（承接第 13.3 条）；三维场景仍然不准加任何贴图。
- ❌ 用颜色做装饰来暗示事实（第 2.1 条）。
- ❌ 墨线压住文字：描边不能盖住正文与数据（第 7 条）。

### 14.8 后台适用本章

后台与公开站点是同一张纸（12.2），因此本章的墨线、硬边偏移影、和紙纤维与标题框**同样适用于后台**；后台不再有玻璃外壳与光晕。

## 15. 产出必须经过一次整体 UI/UX 优化（硬约束）

### 15.1 硬约束

- 每一份产出**至少**做一次**整体** UI/UX 优化。这不是审美偏好，是可核对的要求。
- 「整体」的意思：不是逐项打勾的零碎修补，而是对整个产出做一遍**统一复核**，确认全站只有一套视觉语言 —— 同一个墨线口径、同一个分格节奏、同一个主次层级。
- 风格基准是本方针：和紙墨描的宝石主题（第 14、16 条）。
- 这一轮**不能省**，也不能只做其中一项就算数。

### 15.2 固定件预置主题，降低成本

- 固定件（外壳、共用运行时）已经把这一版主题做好了，随包发布，产出**开箱即带**和紙墨描的宝石主题。
- 所以这一轮优化**不是**从零做主题，而是**核对与落地**：主内容是否第一眼就突出、次级信息是否折叠、层次是否用模型的槽位表达、必要时用外壳的专注开关核对主区是否够大。
- 预置主题是为了降低使用者的优化成本，**不是**把这一轮变成可选项。

### 15.3 必须写进最终说明

最终说明里要有这一轮的记录：改了哪一处、依据哪一条、怎么核对的（打开了什么、看到了什么）。没有记录的产出不算完成这一轮。

## 16. 侘寂配色：依据与硬约束（v3.4 新增）

第 3 节的色板不是「挑好看的」，是**按可说的理由挑的**。本章把理由写下来，并把其中可测的部分变成硬约束 —— 好看是一次性的，约束是长期的。

### 16.1 五个颜料为什么是这五个

| 颜料 | 出处 | 色彩心理学上的作用 | 本产品里的语义 |
|---|---|---|---|
| 藍 `#3d5a72` | 藍染（日本传统的染料色） | 蓝紫色系**降低唤醒度**，在长篇阅读与技术文档里最不疲劳；深而不闷，是「可点」这类高频信号的稳妥色 | 可交互、当前选中、坐标轴 X |
| 藤 `#5f5573` | 紫藤 | 低彩度的紫天然读作「次要、辅助」；与藍同属冷色系，弱对比，适合承托而不抢戏 | 次强调、坐标轴 Y、辅助序列 |
| 柿 `#96501f` | 熟柿 | 橙红**提升亲和与注意触发**，但高彩度橙会制造焦虑 —— 所以取熟透的深赭：留住暖，去掉刺 | 坐标轴 Z、提示 |
| 苔 `#56663a` | 苔（缓生之物） | 绿是公认最不疲劳的色；「苔」意味着缓慢、稳定、不张扬 ⇒ 配「已确认」正好 | 已确认、正常、通过 |
| 錆 `#8a3a2c` | 铁锈 | 「红＝错误」的语义不必改，但鲜红在纸面上过于警报化；铁锈红保留警示、降低攻击性 | 错误、阻断、越界 |

纸与墨同理：**生成り**（未漂白的和纸，暖黄白 `#ebe1ce`）比纯白少一分刺眼；**墨**（暖炭 `#2e2a24`）比纯黑多一分笔触感 —— 纯黑在屏幕上读作「洞」，暖墨读作「写下来的字」。**中性色一律带暖色相**，这是「纸」的物理事实：纸不是中性的。

### 16.2 五条硬约束（可核对）

每一条都写成**可以用尺子量**的样子：给了量法、给了上限、给了实测值。量法写在这里，绑定测试按同一把尺子量色板（`tests/test_three_d.py` 的「第 16 条硬约束」一组用例）。

1. **无纯黑纯白，中性色一律带暖色相**：色板里没有 `#000000` / `#ffffff`；七个中性色（`--gem-void` / `--gem-bg` / `--gem-panel` / `--gem-facet` / `--gem-rim` / `--gem-ink` / `--gem-muted`）的 **HSL 色相**落在 **25°–45°**（实测 34.6°–40.9°）—— 纸不是中性的。
2. **彩度上限用 CIELAB 的 C\* 量**（不用 HSL 彩度：淡色相在 HSL 里会被算得很艳 —— 本色板的纸面 HSL 彩度高达 48.8%，那是公式的错觉，不是纸发艳）：
   - 五种颜料 C\* ≤ **50**（实测 藍 17.4、藤 18.9、苔 27.0、錆 41.7、柿 47.6）；
   - 三维类型色板 C\* ≤ **50**（实测最大 47.6）；
   - 纸的三面（`--gem-bg` / `--gem-panel` / `--gem-facet`）C\* ≤ **12**（实测 10.5 / 7.6 / 11.4）。
3. **明度邻近用 CIELAB 的 L\* 量**：纸的三面两两 L\* 差 ≤ **8**（实测 89.9 / 93.9 / 87.5，极差 6.4；换成 HSL 明度也是 7.6%）—— 侘寂的层次来自**材质**，不来自强对比。
4. **强调色面积 ≤ 5%**：任何一屏里强调色的合计面积不超过 5%。低彩度不是让它到处出现的理由。
5. **对比度下限（WCAG）**：正文 ≥ **4.5:1**（`--gem-ink` 11.00、`--gem-muted` 4.53）；次要文字与**可交互控件的边界** ≥ **3:1**。因此纸面上的控件边界用 `--gem-muted`（4.53:1）或 `--gem-ai`（5.58:1），**不用** `--gem-rim`（只有 2.14:1 —— 那是分隔条与装饰边的弱一档）。五种颜料在纸面上的对比度分别是 5.58 / 5.34 / 4.67 / 4.82 / 5.95，都过正文线。

### 16.3 纸的质地

- 页面底 = `--gem-bg` 纯色 + **和紙纤维**（第 14.5 条）：两层极淡的斜向细线，不承载事实。
- 卡片与面板之间靠**纸的深浅**（`--gem-panel` / `--gem-facet`）与 1px 棱线分层，不靠投影堆叠，也不靠玻璃。
- 硬边偏移影仍在（第 14.3 条），但落点是**深一层的纸**（`--gem-void`）：像一张纸叠在另一张纸上，而不是像光打在物体上。

### 16.4 产出成果与产品同源

- **用户拿到的产出件**（多媒体文档站点）用的是同一张色板：三维实体的类型色（第 4.3 节）取自同样五种颜料的深浅档；三维场景的背景是同一张纸。
- 站点、三维场景、后台与产出件**没有第二套皮**：任何一处出现近似色，都是缺陷。

### 16.5 代价（诚实的取舍）

- 纸面比暗场**更吃对比度**：暗底上霓虹色很醒目，纸面上同样的彩度会「糊」掉 —— 这就是彩度上限与 5% 面积上限的由来。
- 层级比暗场**更依赖棱线**：暗场可以用亮度分层，纸上只能靠 1px 墨线与纸的深浅 —— 所以第 5 条的 1px 棱线是硬要求，不是装饰。
- **可交互性变弱**：淡墨线在纸上的存在感低于亮棱线在暗场上的存在感，所以控件边界一律用 `--gem-muted`/`--gem-ai`（第 16.2 条第 5 项），而不是 `--gem-rim`。
