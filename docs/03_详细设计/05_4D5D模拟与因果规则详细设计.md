## 4D 状态机契约

`DynamicModel {moduleId, stateSet[], initialState, transitions[], eventChannels[], timingModel}`；
`Transition {id, from, on, guard, to, outputs[], evidenceRefs[], ruleStatus}`。

模拟器固定事件排序 `(logicalTime, priority, sequenceId)`；序号唯一。暂停/单步/回退通过事件溯源重放或快照恢复，不可以 UI 动画进度更新为真相。

## 5D 规则语言（安全建议）

采用声明式规则 AST，而非执行任意用户 JavaScript/Python。`Rule {id, if: predicates[], then: effects[], evidenceRefs[], status}`。谓词和效果须来自白名单运算符，拒绝 eval、无限递归和未批准的外部 I/O。

## 传播算法

1. 验证全部 input/output 端口类型一致；构建组合图。
2. 注入干预：修改一组受允许的输入/可用性条件，不直接改结果字段。
3. 基于稳定拓扑和时间队列应用规则；每次写入一条 trace 记录，保留规则、输入、状态快照哈希。
4. 对存在环的图使用时间展开/上界求解；超过 maxEvents/maxSteps 则返回 INDETERMINATE 而非正常结果。
5. 输出基线与干预结果的差异：变化节点、断链、反馈路径、影响证据、假设。

## 结果类型

- `OBSERVED`: 真实执行/日志证据，必须有来源。
- `DERIVED`: 由经定义规则推导的模型结果。
- `HYPOTHETICAL`: 假设干预所产生的推演。
- `UNKNOWN`: 规则缺失/歧义/无法收敛。

## 反事实验收

相同 `scenario+intervention+ruleVersion+seed` 产出同一 trace 语义哈希；修改干预能够计算出不同结果时，应解释影响路径，不能仅切换颜色。Case 示例见 `../08_附录/examples/scenarios.example.json`。
