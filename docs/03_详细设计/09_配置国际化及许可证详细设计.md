## 配置解析顺序

`CLI 参数 > 项目 YAML > Registry 默认配置`；配置中的空字符串代表未设置，不能被解释为有效 URL。所有路径必须根据项目根解析，拒绝目录逃逸。

## 用户输入配置

参见 `../08_附录/gemarc.config.example.yaml`；包含项目源、参考源、模式、维度、语言、模板版本、质量闸门和输出目录。参考源 `borrow` 不能混入目标业务事实。

## 语言处理

界面文字分三层，三层都必须覆盖 `zh-CN`、`ja-JP`、`en-US` 三语：

| 层 | 范围 | 文字的来源 |
|---|---|---|
| L1 工具描述 | `tools/list` 里每个工具的标题与说明 | `src/gemarc_mcp/i18n/<locale>.json` 的 `tools` 段 |
| L2 控制台 | MCP 控制台（`/`）的界面文字 | 同一张表的 `console` 段 |
| L3 账号页 | 账号页与运营区（`/account`、`/account/admin`） | 同一张表的 `accounts` 段 |

- **默认 `zh-CN`**（资源兜底），`ja-JP` 和 `en-US` 必须翻译所有实际 UI 文本、图例和报告标题；术语参照统一词典。
- **唯一来源**：`src/gemarc_mcp/i18n/{zh-CN,ja-JP,en-US}.json`，三张表的键集合必须相同；取不到键时显示键本身并记一条缺口，**不得静默混语**。
- **语言选择顺序**：本机记住的选择 → 浏览器语言（`Accept-Language` / `navigator.language`）→ `zh-CN`。
- **工具描述的交付方式**：MCP 工具的 `description` 字段保持英文（既有行为不变），三语版本放在 `_meta` 的 `gemarc.dev/descriptions` 里，客户端按自己的语言取；控制台与账号页的文字走各自的段。
- **`tools` 段的覆盖范围**：本产品的工具集（`full` 与 `stateless`）的每个工具都有 `zh-CN` 与 `ja-JP` 译文，`en-US` 就是代码里注册的英文说明。GemArc Atlas 工具集（`atlas`、`atlas_remote`）的工具说明**保持英文**：它自己的一套界面文字在 `src/gemarc_mcp/atlas/viewer/i18n/` 里，而且表里没有它的工具时**不写 `_meta`**——只把同一段英文重复三遍会让 `tools/list` 变胖，客户端那边的体积预算过不去。
- 任何 `i18n` 只能影响可显示文本，不得改变模型 ID、边端点、URI、技术协议或证据状态。
- 缺少必需语言资源：strict 模式阻断，非 strict 模式必须明确记录缺口而非静默混语。

## 第三方许可证

- 构件元数据记录 `name/version/SPDX/licenseUrl/noticePath/integrity`。
- 最终发布前，依据锁定版本复核 Three.js、Graphology、Dagre、Dexie、Konva 与构建工具的许可；不得据此文档直接断言所选版本全部可商用。
- 任何字体/图标/贴图/示例图片不得默认视为可分发，必须单独登记权利来源。
