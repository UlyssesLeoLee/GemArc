# 用户个性化设置详细设计

> 文档编号：DD-010 ｜版本：1.1 ｜日期：2026-11-09 ｜状态：设计基线（待评审）  
> 产品：GemArc MCP — 5D Design Scaffolding & Architecture Compiler  
> 说明：本文件为目标设计，不代表目标功能已实现或已测试。

## 1. 目的与范围

账号制部署下，`/mcp` 的认证结果只用来判断「放行还是拒绝」；认证通过之后，调用者的身份没有进入工具层，因此**所有用户看到的工具清单、工具说明与默认行为完全相同**。本设计给每个账号一份自己的设置，并让这份设置在 MCP 协议层真的生效。

三条设计底线：

1. **设置存在真实的数据库里**，不是进程内存、不是浏览器本机存储、不是环境变量。
2. **设置严格按用户隔离**：一个用户的设置永远不会作用到另一个用户身上，任何调用方也不能指定别人的用户标识。
3. **设置只会减少能力，不会增加能力**：工具过滤只能从清单里去掉工具，绝不会把只读令牌变出写工具。

本设计**不做**按用户隔离的工作区：既有登记项 R16 明确「本期不做」，且当前远程部署用的是 `stateless` 工具集（无写工具、无服务器工作区），这项留待工作区存储方案确定后再定。

## 2. 数据存储

新增表 `user_settings`，每个用户至多一行（迁移文件 `0003_user_settings.sql`，与既有迁移同样的「只增不改」规则）：

| 列 | 类型 | 含义 |
|---|---|---|
| `user_id` | `TEXT PRIMARY KEY` | 账号标识，外键指向 `users(id)`，账号注销时随行删除 |
| `lang` | `TEXT NOT NULL` | 界面与工具说明的语言，取值 `''` / `zh-CN` / `ja-JP` / `en-US` |
| `tools` | `TEXT NOT NULL` | 工具白名单，逗号分隔；空串表示「不限制，沿用服务器的全部工具」 |
| `render_profile` | `TEXT NOT NULL` | 渲染形态的缺省值，`''` / `mvp` / `static` / `vite` |
| `updated_at` | `BIGINT NOT NULL` | 最后一次保存的时间（epoch 秒） |

- 行**不需要预先存在**：没有设置的用户按默认值处理（语言**未选择**、不限制工具、`''`），第一次保存时写入。
- **空串表示「没有选择」，不是「中文」**：一个从未选过语言的账号，页面与工具说明都不被按成中文，读者的本机语言（cookie → 浏览器）照旧说了算；只有用户自己保存过一次，语言才固定下来（§4.1）。
- 迁移是**追加**的：不改动 `users`、`api_tokens` 既有列，升级不重写任何既有行，也不对登录路径上的表加锁。
- 时间由应用写入（epoch 秒），SQL 里不调用 `NOW()`，与既有表一致。

## 3. 设置项

| 设置 | 取值 | 缺省 | 作用面 |
|---|---|---|---|
| 语言 | `zh-CN` / `ja-JP` / `en-US` | 未选择 | 控制台界面文字、账号页界面文字、**MCP 工具说明** |
| 工具清单 | 工具名白名单 | 空（不限制） | 该用户 `/mcp` 的 `tools/list` |
| 默认渲染形态 | `mvp` / `static` / `vite` | 空（沿用 `static`） | `gemarc_render` 的 `profile` 参数缺省值 |

设置项的取值在写入时校验：语言必须是三种之一；工具名必须是当前服务器**真实注册**的工具之一（不认识的工具名一律拒绝，不静默丢弃）；渲染形态必须是三种之一或空串。校验失败返回明确的字段级错误，不写入任何东西。

**语言可以显式「不固定」**：语言这一项除了三种语言之外，还有一个合法取值——空串，界面上的说法是「跟随读者」。它的意思是「这个账号不钉语言」，读者的 cookie 与浏览器语言照旧说了算。这不是「默认值」的另一种写法，而是用户**主动选的一个选项**，与渲染形态那一项的「沿用服务器默认（static）」是同一类东西：两者都要能在界面上被选中，也要能被存回空串。

## 4. 生效点

### 4.1 语言

语言选择的优先级（在 DD-009 的顺序上增加最高一档）：

```
账号设置（服务器，用户自己保存过的那个） → 本机记住的选择 → 浏览器语言 → zh-CN
```

- 「本机记住的选择」是浏览器里的 `localStorage`，只在没有登录账号时起作用；登录后以服务器上的账号设置为准，这样换一台机器、换一个 agent 客户端，语言依然是同一种。
- 账号从未保存过语言时，账号设置这一档是**空的**，不参与选择：读者的 cookie 与浏览器语言照旧说了算（和改造前一致），工具说明也仍是英文的正式文本。用户保存一次之后，语言才固定。
- 账号页的语言链接（`?lang=`）**只改这一次浏览**，不写进账号设置；写进账号设置是账号页里那个明确的「保存」动作。
- **保存别的项不会顺手把语言钉住**：账号页的语言下拉里始终有一项「跟随读者」，账号没钉过语言时选中的就是这一项——不是读者当前正在看的界面语言。因此一个只想改工具清单的用户按下「保存设置」之后，账号的语言仍然是空串，不会被读者当时用的语言悄悄定死。
- 「跟随读者」是一个可以主动选回去的选项：钉过语言的人改回它，就把账号的语言重新变回空串。
- 控制台的设置面板里同样有「跟随读者」这一项；控制台顶部的语言切换器仍然是把语言钉到账号上的动作（点了哪种语言，账号就是哪种）。

### 4.2 工具说明的三语下发

- 请求**没有**用户身份时（未登录、共享的环境令牌）：行为不变——`description` 是英文，三语放在 `_meta` 的 `gemarc.dev/descriptions` 里。
- 请求**有**用户身份时：`description` 直接填成该用户语言的译文；`_meta` 仍然带三语，客户端想换语言仍然读得到。三语表里没有的工具保持英文（沿用 DD-009 的「表里没有就不写 `_meta`」规则）。

### 4.3 工具过滤

- 工具白名单为空：该用户看到的工具与服务器注册的完全一致（与今天相同）。
- 工具白名单非空：`tools/list` 只返回白名单里的工具。过滤**只减不增**：写工具仍然还要过令牌作用域与 `can_write` 两道关，白名单不能把它们放出来。
- 白名单非空时，**调用白名单之外的工具一律被拒绝**（工具结果 `is_error=true`，错误码 `GEMARC_ACCT_035`）。否则这份设置只是装饰：清单虽然窄了，客户端照样能直接点名调用。
- 过滤后的清单以该用户的语言下发说明。

### 4.4 默认渲染形态

- `gemarc_render` 的 `profile` 参数**没有**传值时，用该用户的默认渲染形态；账号设置为空时用 `static`（与今天一致）。
- 调用方**显式传值**时以调用方为准：个性化是缺省值，不是强制值。
- 为了分得清「没有传值」与「显式传了 `static`」，该参数的缺省值从 `"static"` 改为**空串**：`""` 表示「用我的缺省值」。这条改动会出现在 `tools/list` 的 `inputSchema` 里（`profile` 的 `default` 由 `"static"` 变成 `""`），因此写在这里，也写进《MCP 工具详细契约》。

## 5. 读写路径

| 入口 | 方法 | 认证 | 说明 |
|---|---|---|---|
| `/account/settings` | `GET` | 登录会话 | 返回该用户的设置（JSON），含服务器真实注册的工具名清单 |
| `/account/settings` | `POST` | 登录会话 + CSRF | 保存设置（表单），保存后回到账号页。语言可以是空串（跟随读者） |
| `/mcp` | — | 令牌或会话 | 读设置并生效，不接受任何「指定用户」的参数 |

- 账号页（`/account`）新增「我的设置」一节：一个语言选择、若干工具勾选框、一个渲染形态选择、一个保存按钮。不用脚本也能用。
- 控制台的顶部语言切换器**同时**保存到账号设置（这样在控制台切换语言，agent 侧看到的工具说明也跟着变）。控制台读到的设置以服务器为准，本机存储只作为未登录时的兜底。
- 保存后立即让该用户的令牌缓存失效：设置不必等到缓存过期才生效。

## 6. 令牌存储（不变的部分）

- 令牌**已经**存在真实的数据库里：生产是 Postgres（Neon），`api_tokens` 表存 `secret_hash`（SHA-256 域分离哈希）、公开标识、作用域、有效期、`last_used_at`、`revoked_at`；令牌可吊销、可审计、每人有上限。
- **明文不进数据库**（既有政策 D110：只存无密钥哈希，明文只在签发那一刻出现一次）。数据库被读走也拿不到可用令牌。
- 用户想再拿到一个能用的令牌，走「随时重新签发」：账号页签发新令牌，旧的可单独吊销。**本设计不改变这条**：把明文也存进数据库等于让密钥环泄露变成全部令牌泄露，与现有安全基线相反。
- 个性化设置里**没有任何密钥**：语言、工具名、渲染形态都是公开信息。

## 7. 隔离与失败处理

- 设置的读写与生效都只以**认证得到的用户标识**为依据；接口不接受路径参数、查询参数或请求体里的用户标识。
- 数据库读失败：MCP 请求按既有纪律回 `503`（`GEMARC_ACCT_002/003/004`），**绝不**当作「没有设置」而放行。
- 设置行缺失或损坏（语言不在允许集合内）：按缺省值处理，并在审计日志里记一条，不让一条坏数据把整个 `/mcp` 变成 500。
- 工具白名单里的工具在服务器上已经不存在（服务器换了工具集）：跳过它，不因此拒绝整个请求。

## 8. 验收要点

1. 两个账号各有各的设置：A 的工具白名单不含某个工具时，A 的 `tools/list` 里没有它，B 的仍然有；两者互不影响。
2. 账号设置为日文时，该账号的 `tools/list` 里每个工具的 `description` 是日文，`_meta` 里仍带三语；未登录请求的 `description` 仍是英文。
3. 未设置白名单的账号，`tools/list` 与服务器注册的工具完全一致（与改造前逐项相同）。
4. 只读令牌即使把写工具写进白名单，也拿不到写工具（作用域关仍然有效）。
5. 保存设置后，下一次 `/mcp` 请求立刻生效（不必等缓存过期）。
6. 数据库不可用时 `/mcp` 回 `503`，不回 `401`，也不放行。
7. 明文令牌不出现在数据库、URL、日志里；令牌列表页不显示任何可还原的片段。
8. 账号页在不用脚本的情况下可以保存设置；控制台切换语言后 agent 侧的工具说明语言跟着变。
9. 白名单非空时，点名调用白名单外的工具得到 `is_error=true` 的拒绝，白名单内的工具照常可用。
10. 账号设置了 `render_profile=vite` 且调用方**没有**传 `profile` 时，产物是 vite 形态；调用方显式传 `profile=static` 时以调用方为准。
11. 没有任何账号设置、也没有任何身份时，`/mcp` 的 `tools/list` 与改造前**逐字节相同**（含 `inputSchema` 里 `profile` 的缺省值由 `"static"` 变为 `""` 这一处已记录的差异除外）。
12. **保存别的项不会钉住语言**：账号从未保存过语言时，账号页的语言下拉选中的是「跟随读者」；此时只改工具清单再保存，账号的语言仍然是空串，读者当时正在看的界面语言不会被写进账号。反过来，主动选中「跟随读者」再保存，账号的语言回到空串。
