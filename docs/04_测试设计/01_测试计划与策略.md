# 测试计划、环境及策略

> 文档编号：TP-001 ｜版本：1.0 ｜日期：2026-10-25 ｜状态：设计基线（待评审）  
> 产品：GemArc MCP — 5D Design Scaffolding & Architecture Compiler  
> 说明：本文件为目标设计，不代表目标功能已实现或已测试。

## 目标

验证 FR/NFR 的实现满足需求，重点关注事实可信性、组件复用、维度一致性、MCP 工具安全、模拟可复现与交付完整性。

## 测试类型及责任

| 层级 | 对象 | 入口条件 | 退出条件 |
|---|---|---|---|
| UT（単体） | Schema/Registry/Compiler/State/Causality 独立单元 | 详细设计与接口评审通过 | 全部 P0 UT 通过，核心逻辑覆盖率≥90% |
| IT（結合） | MCP→Core→Viewer→Export | 核心 UT 通过且依赖锁定 | 组件间接口/错误回退无 P0 缺陷 |
| ST（システム） | 目标端到端与 NFR | IT 通过且基准环境就绪 | 全部 P0 FR/NFR 可复现、无致命缺陷 |
| UAT（受入） | 用户目标与产物审查 | ST 报告、风险列表齐备 | 需求方签字同意，并记录留存风险 |

## 测试环境定义

- 固定源码 Commit、Core/MCP/Viewer 版本、Node/Python 版本、OS、WebGL 和浏览器版本。
- 一组真实小型仓库（事实来源可审）、一组带循环关系的大型合成模型、两组不同业务仓库做组件复用对照。
- 评测 Agent Prompt 需固定版本、模型及采样设置；Token 统计保持交付范围相同。
- 安全用例使用独立沙盒及最小权限账户，禁止访问真实生产凭据。

## 缺陷等级

P0：伪造 confirmed 事实/越权文件写/交付中断/确定性因果误标；P1：功能不正确或性能严重下降；P2：一般 UI 问题；P3：非阻断建议。

## 执行记录规则

本包只提供用例、环境、期待值；**未执行任何新功能测试**。实际执行时记录执行者、时间、版本、日志证据、实际值与 Pass/Fail。报告不可根据设计文档自动填“通过”。
