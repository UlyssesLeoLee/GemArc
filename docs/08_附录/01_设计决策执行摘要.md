# 架构决策与执行摘要

## 最终目标设计

GemArc MCP 是一个“标准化 5D 资料编译与交付系统”。它以本地优先的核心架构模型为事实源，通过 MCP Tools/Resources/Prompts 和复用的 Viewer/组件库，生成形式一致、可审计的 1D–5D 资料及 Konva 多标签原型。

## 应落实的五项架构决策

1. MCP Adapter 与编译 Core 分离；不把完整网页源码塞给 AI Prompt。
2. Schema & Evidence 为唯一事实依据；View/Dimension 只做投影，不能增加虚构事实。
3. Component Registry 保存外观、行为、事件、许可和测试契约，由 AI 查询而不是每次重写。
4. 4D/5D 使用可重放的事件和因果规则，严格区分观测/推导/假设。
5. Build Lock + Validator + ST/UAT 形成放行制度，质量不能只依赖模型的自我评价。

## 开发起点

优先复用已有 Viewer/Python 脚本，把目前成熟的 2D/3D 能力适配到模型/Registry；新的 4D/5D、Konva/Dagre/Graphology/Dexie 应分期开发与真实测试。
