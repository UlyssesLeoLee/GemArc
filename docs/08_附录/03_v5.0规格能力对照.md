# v5.0 规格能力对照（MCP 侧）

> 文档编号：APP-003 ｜版本：1.0 ｜日期：2026-11-03 ｜状态：设计基线（待评审）  
> 产品：GemArc MCP — 5D Design Scaffolding & Architecture Compiler  
> 规格来源：`Universal_5D_GemArc_Web_v5.0`（30 节完整前端工作台规范）  
> 说明：本文只登记**已实现且有测试覆盖**的部分。标「目标工程」的条目不由 MCP 承担：MCP 负责模型与计算权威，前端工作台由使用 MCP 的工程实现。

## 1. 职责边界（先说清楚谁做什么）

| | MCP（GemArc） | 目标工程（使用 MCP 的 Web 工作台） |
|---|---|---|
| 是什么 | 规范化模型、词表、契约、校验、4D/5D 计算、GWF-IR、派生数据文件 | React/Three/Graphology/Dexie/Sigma/Dagre/Konva 的前端工作台 |
| 产出 | `data/*.json`（模型 + 派生文件）、校验结论、模拟轨迹 | 可运行的 HTML 站点与交互 |
| 不产出 | 宝石几何、材质、画布交互、浏览器存储、原型标签页 | 事实（事实只能来自证据） |

规格 §25 的目录是**目标工程**的目录约定。MCP 侧一一对应的交付物是：

| 规格 §25 目标文件 | MCP 侧对应物 | 由谁产生 |
|---|---|---|
| `architecture/architecture.json` | `data/architecture.json` | `gemarc_render` / `gemarc_build` |
| `architecture/evidence-index.json` | `data/evidence-index.json` | `gemarc_render` |
| `architecture/`（图示清单） | `data/diagram-catalog.json` | `gemarc_render` |
| `architecture/spatial-layout.json` | `data/spatial-layout.json` | `gemarc_render` |
| `workflow/workflow-schema.json` | `data/workflow-schema.json` | 随固定件（kit）发布：只依赖词表，不随模型重复传输 |
| `workflow/workflow-ir.json` | `data/workflow-ir.json` | `gemarc_render` |
| `workflow/case-library.json` | `data/case-library.json` | `gemarc_render` |

> 图示清单那一项在 MCP 侧换了个名字：规格给目标工程定的那个文件名属于参考系统，在本仓库的哈希禁词表上（`tests/atlas/denylist.sha256`），写进本仓库会违反既有的防泄漏门禁。内容一致，只是文件名不同；详见 `08_附录/04_v5.0实施缺陷提交单.md` 的 D-05。

## 2. 逐节对照

| 规格节 | 标题 | MCP 覆盖 | 证据 / 边界 |
|---|---|---|---|
| §01 | 输入优先级与运行约束 | 间接 | MCP 不读取仓库；事实由调用方 agent 用自己的文件能力取得后内联传入 |
| §02 | 角色、任务与完成条件 | 否 | 属目标工程的协作流程 |
| §03 | 真实仓库分析与规范化架构模型 | **是** | 实体种类 20（含规格 18 种）、证据等级 6 与规格完全一致；`node`/`edge`/`evidence` 的 Schema 覆盖 §3 的 node_fields / edge_fields / provenance_fields；`qualifiedName` / `sourceLocation` / `version` 已补齐且可选 |
| §04 | Browser-Native Property Graph Engine | 部分 | MCP 侧运行时（`runtime/graph/`）提供图存储与查询；Dexie 持久化、Graphology 索引、Web Worker 属目标工程 |
| §05 | Node 与 Edge 独立点击查阅 | 模型层是 | Node/Edge 是一等实体（独立 id、方向、类型、条件、证据）；点击与选中属前端 |
| §06 | 图查询、路径与子图探索 | 部分 | MCP 运行时提供邻域/路径/子图；交互界面属目标工程 |
| §07 | Building–Floor–Room 三维语义空间 | **是** | `space-levels` 词表（Building/Floor/Room）+ `spaceSpan` 跨空间关系 + `data/spatial-layout.json`（含 `missing`：没有空间就明说没有） |
| §08 | Focus–Context 动态退避 | 否 | 属前端交互 |
| §09 | UML、ER 与 Architecture View | **是** | 图示类型 21 种，覆盖 §9 三个家族的全部条目（`specFamilies` 可机读）；`diagram-catalog.json` 按保真要求逐项标 `missing`，不伪造 |
| §10 | 三维宝石专用图示语法 | 否 | 宝石几何/材质/图鉴属目标工程；MCP 只保证 3D 视图的语义与空间归属 |
| §11 | 0D–5D 表达模型及 View 变化 | **是** | `view.dimension` 的 1D–5D 枚举；View 与维度正交由 `view.schema.json` 约束 |
| §12 | 4D 离散事件模拟与可回放 | **是** | `gemarc_simulate`（逻辑时钟、事件轨迹、可重复回放）；确定性由黄金用例 `simulation-golden.json` 钉住 |
| §13 | 5D 多 Case 因果系统 | **是** | 新增 `case-types.json`：14 种分析类型 + §13 case_contract 字段 + §14 的 18 个动画原语；`cases[].category`（5 类分诊轴）与 `cases[].caseType`（分析类型）互补；`cases[].reality` 承载 Observed/ImplementedModel/DesignedModel/Hypothetical |
| §14 | 5D Causal Animation Grammar | 部分 | 原语与终态已登记并按 Case 类型给出候选组合；动画本身由前端消费计算轨迹渲染 |
| §15 | 因果干预、分歧传播与多情景比较 | **是** | `gemarc_simulate` 的 `compare_baseline` + `disabled_nodes`（规则化 what-if，非因果识别）；首差定位与分歧子图在轨迹里 |
| §16 | AI-Native Infinite Workflow Canvas | 否 | 页面属目标工程；它需要的语义由 §17 的 GWF-IR 提供 |
| §17 | 版本化 GWF-IR | **是** | `workflow-kinds.gwfIr` 登记 §17 的工作流/节点/边/端口字段目录与 19 种节点类型、7 种边类型；`workflow.schema.json` 覆盖全部字段；`data/workflow-ir.json` 按 §17 字段名输出（含 `designOnly` / `executable` / `issues`） |
| §18 | 主流画布与流程格式互操作 | 部分 | 运行时提供适配器骨架与往返测试口径；JSON Canvas / BPMN2.0 / ReactFlow / Mermaid 的完整实现属目标工程，损失报告由其负责 |

## 3. 「能妥善实现」的可核对口径

| 主张 | 怎么核对 | 现状 |
|---|---|---|
| 模型能表达规格逐条列出的每个字段与枚举 | `tests/test_v5_spec_coverage.py`：把规格里的字段与枚举原样抄进断言 | 33 项断言，覆盖 §3 / §9 / §13 / §14 / §17 / §25 |
| 规格拼写与正本拼写都能用 | `tests/test_v5_spec_coverage.py` 的 `AliasTests` | `type`/`label`/`direction`/`nodeType`/`edgeType`/`guard`/`portId`/`caseId` 等别名被接受并归一 |
| 派生文件与模型一致 | `tests/test_v5_spec_coverage.py` 的 `DerivedFileTests` | 证据索引的反向引用、图示缺失项、空间落位、GWF-IR 字段名、Case 契约逐项对拍 |
| 渲染与本地构建逐字节一致 | `tests/test_stateless.py` 的 `test_render_plus_kit_equals_build_byte_for_byte` | kit + `gemarc_render` 的文件 == `gemarc_build` 产出的文件 |
| 缺失信息被标为缺失而非伪造 | `diagram-catalog.json` / `spatial-layout.json` / `workflow-ir.json` 的 `missing` 与 `issues` 字段 | 保真元素探测表覆盖全部 fidelity token；未登记的 token 一律记为缺失 |

## 4. 明确不做的事

- **不由 MCP 生成的**：三维宝石几何与材质、无限画布交互、原型标签页、浏览器端持久化、适配器的完整实现、AI Patch 引擎、真实浏览器验收。这些是目标工程的实现责任；MCP 只保证它们所依赖的语义契约是完整且可机读的。
- **不由 MCP 判定的**：因果识别（§15 的干预比较是规则化 what-if，不证明真实世界的因果关系）、证据等级的真假（事实由证据决定，MCP 只校验一致性）。
- **不承诺的**：交互质量、性能指标、浏览器兼容性——这些需要目标工程的真实浏览器验证。
