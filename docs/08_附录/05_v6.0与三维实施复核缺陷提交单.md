## D-09（中）atlas CLI 的 `put` 在选项之后不接受 `-`

| 项 | 内容 |
|---|---|
| 位置 | `src/gemarc_mcp/atlas/cli.py:76-84`（`put` 子命令的解析器） |
| 现象 | `python -m gemarc_mcp.atlas put <项目> <切片> --mode patch -` 退出码 2，报 `error: unrecognized arguments: -`；把 `-` 挪到选项之前（`put <项目> <切片> - --mode patch`）则能正常解析 |
| 成因 | `stdin` 声明成**可选位置参数**（`nargs="?"`）。argparse 遇到夹在中间的可选项时会把位置参数切成两段，后一段没有可填的位置参数了，于是报「无法识别的参数」 |
| 证据 | 2026-11-04 实测（仓外探针 `E:\GemArcWork\probe_atlas_cli.py`）：两种参数顺序同一条命令，前者退出码 2 + argparse 报错，后者通过参数解析 |
| 影响 | ①「从标准输入打补丁」这条常用路径在 CLI 上不可用；② `tests/atlas/test_cli.py::LendingDeskSessionTests::test_scripted_session` 正是用这个写法，因此**长期挂在基线失败里**（自 2026-11-02 的基线日志起就在，14 条基线失败中的 2 条与本条同源）；③ `test_forty_node_session` 同类 |
| 建议处置 | (A) 把 `stdin` 从可选位置参数改成显式选项（如 `--stdin`），或给 `put` 加一个 `parse_known_args` 兜底把尾部 `-` 收进来；(B) 保留现状，改测试的调用顺序为 `put <项目> <切片> - --mode patch`，并在 CLI 帮助里写明 `-` 必须放在选项之前；(C) 记为已知项 |
| 本轮是否已改 | **否**（既有实现，按规矩交裁定） |

## D-10（中）`test_atlas_publication_gate` 用 `python -I` 起子进程

| 项 | 内容 |
|---|---|
| 位置 | `tests/atlas/test_atlas_publication_gate.py:386` |
| 现象 | 该测试把仓内 `api/`、`src/`、`examples/demo-site/` 复制成一份上传集，再用 `python -I` 起子进程验证「上传集里不含 atlas 包」。子进程报 `ModuleNotFoundError: No module named 'anyio'`，测试断言 `returncode == 0` 失败 |
| 成因 | `-I` 是隔离模式，等于 `-E -s`：既屏蔽环境变量（含 `PYTHONPATH`），也屏蔽**用户目录的 site-packages**。本机的 `anyio`／`starlette`／`mcp` 全部装在 `%APPDATA%\Python\Python312\site-packages`（`C:\Python312\Lib\site-packages` 是空的），于是隔离子进程一个都导入不到 |
| 证据 | 2026-11-04 实测：`python -c "import anyio"` 成功且路径在用户目录；`python -I -c "import anyio"` 直接 `ModuleNotFoundError` |
| 影响 | 凡是用 `pip install --user` 装依赖的机器（很常见），这一条**必然失败**，与被测代码无关，却长期占着基线，掩盖真实回归 |
| 建议处置 | (A) 把 `-I` 换成 `-s`（只屏蔽用户目录，仍允许解释器自身的 site-packages 与 `PYTHONPATH`），保留 `PYTHONPATH=""` 防止串味；(B) 保留 `-I` 但在测试里先探测依赖可见性、不可见就 `skipTest` 并给出提示；(C) 记为已知项，约定套件必须在虚拟环境里跑 |
| 本轮是否已改 | **否** |

## 已销案：space-viewer 测试的投影约定

之前登记过一条「space-viewer 测试辅助函数的投影约定与 three/stub 不一致（一个用 `forward × right`，另一个用 `right × forward`）」。2026-11-04 逐行复核后**不成立**：

- `src/gemarc_mcp/scaffold/runtime/tests/space-viewer.test.mjs:99-100`
- `src/gemarc_mcp/scaffold/runtime/tests/axis-viewer.test.mjs:78-79`
- `src/gemarc_mcp/scaffold/runtime/tests/helpers/three-stub.mjs:558-559`

三处写法**完全相同**：`right = forward × worldUp`、`up = right × forward`。这与 three.js 的 `x = up × z`、`y = z × x`（其中 `z = −forward`）等价。测试桩里另一处投影（`three-stub.mjs:129-132`）用的是 `backward` 表述，展开后同样是这两条。⇒ 销案。
