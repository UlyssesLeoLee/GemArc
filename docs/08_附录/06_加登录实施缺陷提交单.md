+    if console_gated:

+        location = response.header("location")

+                    response.status in (302, 303, 307) and (location or "").rstrip("/").endswith("/auth/google/start"),
+                    f"{describe(response)} Location={location!r}")

## A-02（低）全量套件基线里的两条失败，根因已经查清——都是**环境/工具链与断言写法不匹配**，不是产品代码缺陷

> 这两条在 2026-11-03 的基线里就存在，**本轮逐条比对确认失败集合与基线完全一致（14 条、8 个模块）**，没有新增。下面是把根因从「报错信息吞掉了真实原因」细化到具体一行。

### A-02.1 `tests/atlas/test_derive_fragments.py::JavaScriptTwinTests::test_node_twin_check_passes`

- **断言**：脚本第 309 行 `self.assertIn("# fail 0", run.stdout)`。
- **实际输出**：本机 Node 24.19.0 的 `node:test` 报告器输出的是 **`ℹ fail 0`**（Unicode 信息前缀），不是旧版 TAP 的 `# fail 0`。
- **实质结论**：该用例检查的**内容全部通过**——输出里 `ℹ tests 8 / ℹ pass 8 / ℹ fail 0`，8 个夹具的 JS 与 Python 组装逐字节相等。**只是标记串变了。**
- **为什么基线里报的是 ERROR**：基线那轮子进程没起来（`run.stdout` 为 `None` ⇒ `TypeError: 'NoneType' object is not subscriptable`），断言的真实原因被吞掉——这正是 `05` 号单里 **D-11** 记的那类问题。本轮它在资源充足时起来了，于是失败形态从 ERROR 变成 FAIL。**同一条用例，两种失败形态，都是环境问题。**
- **可选处置**：(A) 把断言改成同时接受两种标记（`"# fail 0" in out or "ℹ fail 0" in out`），并把 `ℹ` 一并按 UTF-8 读取；(B) 固定 Node 版本到仍输出 `# fail 0` 的旧版；(C) 改用 `node --test --test-reporter=tap` 强制 TAP 输出后再断言。
- **我的处置**：**未改**（属既有测试实现）。这是**环境漂移**，不是产品缺陷，优先级低。

### A-02.2 `tests/atlas/test_atlas_publication_gate.py::AtlasKitRouteTests::test_the_vercel_upload_set_cannot_serve_the_kit_even_with_the_flag`

- **断言**：脚本第 388 行 `self.assertEqual(done.returncode, 0, ...)`，子进程报错为 `File "<temp>\api\index.py", line 90, in <module> import anyio` → `ModuleNotFoundError: No module named 'anyio'`。
- **根因**：子进程用 `python -I`（隔离模式）启动，**隔离模式会排除用户目录下的 site-packages**；而本机的 `anyio` 装在 `%APPDATA%\Python\Python312\site-packages`（用户目录），因此必然 import 不到。
- **对应既有单据**：`05` 号单的 **D-10** 已经记的就是这一条（"用 `python -I` 起子进程，依赖装在用户目录的机器上必然失败"）。本轮只是把证据补齐到具体行号与具体错误串。
- **可选处置**：(A) 子进程改用普通 `python`（去掉 `-I`）或补 `-s`；(B) 换用虚拟环境解释器；(C) 记为已知项，依赖装到非用户目录。
- **我的处置**：**未改**（属既有测试实现）。
