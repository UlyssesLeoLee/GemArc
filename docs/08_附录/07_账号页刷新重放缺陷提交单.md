# 账号页刷新重放与令牌重复缺陷提交单（2026-11-11）

> 范围：账号页（`/account`）与控制台在「状态变更之后刷新页面」这一类交互上的**发现但未自行修复**的缺陷。
> 规则遵循既有惯例：**发现者提交、修改者另行裁定**。本单只登记与给证据，不动既有实现。
> 触发：用户在生产上发现「生成密钥后刷新网页会再制作同名密钥」，于是对账号区做了一轮整体审查。
> 相关单据：`04_v5.0实施缺陷提交单.md`、`05_v6.0与三维实施复核缺陷提交单.md`、`06_加登录实施缺陷提交单.md`（A-01…A-06）。
> 取证脚本（仓外）：`E:\GemArcWork\probe_refresh_duplicate.py`；原始输出：`E:\GemArcWork\probe_refresh_duplicate.txt`。
> 取证方式：假 IdP + 临时 SQLite + 本机 `127.0.0.1` 实例，不连任何网络服务，不涉及任何真实凭据。

## R-01（高）刷新账号页会再创建一个同名令牌 —— 用户在生产上看到的现象

| | |
|---|---|
| 位置 | `src/gemarc_mcp/accounts/routes.py`：`_create_token`（`:753`）、`_render_account`（`:587`）；`src/gemarc_mcp/accounts/pages.py`：令牌表单（`:407`）与一次性的明文显示框（`:374`） |
| 根因 | `POST /account/tokens` 成功后回的是 **200 + 重绘的账号页**（响应里没有 `Location` 头），不是 303 重定向。浏览器在 POST 结果页上按 F5（或后退回退到该页）会**重发同一个 POST**，于是又走一遍创建逻辑。CSRF 值由会话派生、刷新后不变，所以重放能过 CSRF 校验；令牌名没有唯一性约束，于是第二次创建成功，并且与第一个同名 |
| 证据 | 下方「本地实测原始输出」A1–A9 |
| 影响 | ① **静默多出一个仍然有效的凭据**：第二个令牌是活的、能通过 `/mcp` 鉴权（A8 = HTTP 200），而第一个令牌的明文已经被第二次的显示顶掉（A6 = False、A7 = True）——用户手里留下一个**明文已丢失但依然有效**的令牌，只能自己在列表里找到它并撤销；② **占名额**：每个活令牌占用户 10 个名额之一，反复刷新会把名额占满（B2 = 10 个同名令牌），之后正经创建会撞上限；③ **事后可查**：审计表里有两条 `token_created`（A9 = 2） |
| 可选处置 | (A) **改成 POST-重定向-取（PRG）**：创建成功后回 303 到 `/account`，明文放进服务端一次性的短时槽位（会话内、约 60 s、只读一次），由随后的 GET 取走并立刻清除。刷新 GET 不会再创建，明文也只显示一次——与既有约定「明文只在这次响应里显示一次」（`docs/09_部署/02_账号与安全.md` 第 3.14 节）一致；(B) 303 + 把明文放进一枚一次性 HttpOnly Cookie，GET 时取走并清除；(C) 表单带一次性幂等键（服务端记住已用过的键），同一个键的第二次请求拒掉或返回第一次的结果（要新增存储与过期策略）；(D) 只加「同名即拒绝」：改动最小，能挡住用户看到的现象，**挡不住**明文丢失与双击；(E) 前端点一次就禁用按钮：**只能挡双击，挡不住刷新**（刷新会重置页面状态） |
| 连带 | 选 (A)/(B)/(C) 都要动既有测试：创建令牌的 POST 现在断言的是 200（`tests/accounts/test_routes.py` 的 `:359`、`:377`、`:542`），`tests/accounts/test_acct_fix.py:179`、`tests/accounts/test_flow_privacy.py:74`、`tests/accounts/test_integration_app.py:29`（以及它的调用点 `:131`）也按「响应体里有明文」取值——PRG 之后明文在**下一个**响应里，取值写法要一起改 |
| 我的处置 | **未改**（(A)–(E) 都要用户裁定）。取证脚本与输出留在仓外，裁定后即可套用；(A) 需要动 `sessions` 或新增一张「一次性明文」表，属于设计改动，所以一并请用户拍板 |

## R-07（提示）令牌名没有唯一性约束

事实：`api_tokens` 表与 `tokens.create()`（`tokens.py:191`）都不约束同一用户下的令牌名，所以十个同名令牌可以并存（B3：名字集合 = `['laptop']`）。设计文档没有要求唯一，所以**不算缺陷**；但它让 R-01 的重复很难被一眼看出来（列表里两行同名，只有 8 位公开 ID 不同）。若采纳 R-01 的 (D)，要同时说明「同名即拒」是产品规则而不是实现细节。

## 这一轮审查**没有**发现问题的部分

- 账号页的响应都带 `Cache-Control: no-store`（`pages.py:53`）——页面上那一次明文不会被中间缓存或磁盘缓存存下；
- 控制台的令牌只进 `sessionStorage`，不进 `localStorage`、不进 URL（`console.js:106` 起的注释与实现）；
- 撤销单个、撤销全部、在所有设备登出、运营区的五种动作、运营区设置与站点重建，**全部回 303**（C3 = 303），刷新重放安全；
- GET 从不改状态（`tests/accounts/test_routes.py::test_get_never_changes_state` 守着）。

## 本地实测原始输出

```
A1 first POST /account/tokens      -> HTTP 200 | live tokens: 1 | names: ['laptop']
A2 the response is a PAGE, not a redirect -> Location header: None
A3 refresh replay (same POST again)  -> HTTP 200 | live tokens: 2 | names: ['laptop', 'laptop']
A4 every replayed token is still live -> True
A5 the CSRF token is unchanged, so the replay passes the CSRF check -> True
A6 the FIRST plaintext is still shown after the refresh -> False
A7 the SECOND plaintext is shown instead -> True
A8 the orphaned first token still authenticates on /mcp -> HTTP 200
A9 the audit log records both creations -> 2 rows of token_created
B1 twelve identical POSTs            -> statuses: [200, 200, 200, 200, 200, 200, 200, 200, 200, 200, 429, 429]
B2 live tokens in the table          -> 10 (the per-user cap is 10)
B3 every live token carries the SAME name -> ['laptop']
B4 one more creation                 -> HTTP 429 | body mentions GEMARC_ACCT_033: False
C1 POST /account/settings            -> HTTP 200 | replay HTTP 200
C2 POST /account/export              -> HTTP 200 | replay HTTP 200
C3 POST /account/tokens/revoke-all   -> HTTP 303 (303 = replay safe)
C4 sessions after the revokes         -> 1
D1 POST /account/delete              -> HTTP 200 | replay HTTP 401
D2 the replay body mentions GEMARC_ACCT_020 -> True
E1 seven exports (one is a refresh)   -> statuses: [200, 200, 200, 200, 200, 429, 429]
E2 the daily export quota is 5, so a refresh can use it up -> True
```

补充说明：B4 的 429 是**限流**（`pat_create` 10 次/小时，`ratelimit.py:23`），不是**名额上限**（10 个活令牌，`tokens.py:83` 与 `:211`）；两者数值相同，所以先撞到的是限流。
