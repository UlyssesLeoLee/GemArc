# 成本：把 token 花在事实上

- 一次 put 最多约 3K token；169 个节点的系统约 25 次 put。一次修复补丁是 1-6 行（每行约 45 token），加上约 1K token 的诊断。
- 不要重发有效的行，不要重读切片：put 回复里的 `next` 行告诉你做什么，`status view=next`（约 1 KB）用于红稿、续接或每 5 次 put 左右，`index` 告诉你已有什么。
- 诊断只打印一个根因，后果记为 derived。先修列出的第一条错误。
- 每个切片最多修 3 轮；总共大约每 11 个节点 put 两次；超出就汇报 `blocked` 并附最后的诊断，不要空转。
- as-is 项目里读源码占大头：先看文件大纲，引用唯一锚点，不要把代码粘进行里。
- sub、label、title 各写一短行；文档负责结构，你负责事实。
