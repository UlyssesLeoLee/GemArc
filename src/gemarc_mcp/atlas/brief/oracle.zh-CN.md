# 期望（oracle）：期望是意图

- `expect` 行（以及干预的 class 和 terminal）写的是应该发生什么。依据需求或你读到的代码，在任何仿真之前写。绝不要把引擎结果抄进去。
- 写入类调用会在期望所指的每个节点都能解析时给它盖章。在任何判定之前盖章的保持 `sealed`；在出现不一致报告或揭示之后再改，就变成 `revised`；`by=user` 只有用户确认之后才算数。
- 判定是盲的：只给通过或失败，以及有多少个被断言的节点不一致，不说是哪些。点名属于揭示，会被记录。
- 被断言的节点至少要覆盖用例参与者的 max(2, 35%)。abnormal、recovery、combined 类用例如果只断言 Completed，会得到 OR-002。
- 发布构建要求每条期望都是 sealed 或 confirmed。期望确认单列出用户尚未确认的条目；由用户批准，你永远不要写那个文件。
