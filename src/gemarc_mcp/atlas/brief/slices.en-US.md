# Slices and put

- One slice is one `.atl` text, named `[a-z0-9-]{1,40}`. Number them in reading order: `00-space` (buildings, floors, rooms), `10-structure`, `11-structure` ... (nodes, edges, evidences, machines, transitions), `20-scenarios` ... (tests, cases, events, expect, interventions, requirements, tbds, policies).
- Size: about 11 nodes with their edges and evidences per slice (4-7 KB). Over 8 KB is SZ-001, over 64 KiB is refused. A 100-node system is about ten structure slices plus the scenario slices.
- `put(project, slice, text, mode, format, base)`: no ERROR commits (WARN and INFO never block) and archives the old version (10 kept). Any ERROR commits nothing and keeps your whole text as the slice's red draft: nothing is lost.
- Repair with `mode=patch`, never by re-sending or re-reading the slice. A patch applies to the red draft if there is one: a row with the same identity replaces the row (identity: id; edge from|rel|to; expect case; transition machine + from|to); `-svc.old` or `-a | calls | b` deletes a row; an events block (`@set case=X` and its rows) replaces all events of that case, an empty block deletes them. A replacing row that brings no `@set` line keeps the `@set` defaults of the row it replaces. An empty patch (only `#atlas 1`) re-checks the red draft, for example after the slice it waited for was written. A typical repair is 1-6 rows.
- The same text gives the same sha8 and `unchanged:true`. `base=<sha8>` rejects the write when the slice changed meanwhile (CONFLICT, nothing written).
- A slice may reference any id and defines only its own; defining an id twice is ST-002 naming both places. An id that is not defined yet is pending (INFO) or, when one edit from a defined id, a WARN typo: do not chase it, write the slice that defines it next. Write the edges, then `@final edges`, then the cases.
- To resume or after losing context: `status view=next`. Read the lines in order: the leading digit is the priority (1 red draft or error, 2 BLOCK slot, 3 undefined ids, 4 requirement gaps, 5 cases without expectation, 6 unreachable states, 7 coverage); the last line is the dimension readiness 1D-5D. `phase` is collect, author, repair, build, review, done or needs-user: on needs-user stop and ask the user, never invent.
- `index` lists what exists (nodes, room:<id>, req:<id>, case:<id>, ids:<prefix>) in compact lines. `check` never writes: mode=slice per slice, mode=full for the project (every red draft is ST-009, listed with what it leaves undefined: repair the drafts first).
